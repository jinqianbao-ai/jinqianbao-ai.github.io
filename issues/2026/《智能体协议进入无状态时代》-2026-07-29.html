MCP 2026-07-28 发布：从有会话连接改为无状态请求响应

模型上下文协议 MCP（Model Context Protocol，用来让 AI 智能体连接工具、数据和应用的开放协议）发布 2026-07-28 版。官方博客称，Tier 1 SDK 每月下载量接近 5 亿次，TypeScript 与 Python SDK 总下载量均已超过 10 亿次。

最大变化是协议核心从双向、有状态连接，转向无状态的请求/响应模式；旧的 initialize/initialized 握手和 Mcp-Session-Id 会话头被移除，请求本身携带协议版本、客户端身份和能力信息。这样任何请求都可以落到普通轮询负载均衡后的任一服务器实例，不再要求共享会话存储。

与主线的关系：这是今天最重要的一手信号。智能体工具连接从“开发者本地能跑”进入“网关、WAF、缓存、负载均衡都能接”的阶段。

1. MCP 新规范取消会话依赖，网关可以按请求头路由工具

三、📚 AI实用教程（三线连载第 2 期）

本期固定推进三条主线：Claude Code、Hermes Agent 与 Claude 模型。教程全部依据公开官方文档，命令与代码只作为读者可复制示例，不涉及本机维护或诊断。

Claude Code 系列｜第 2 期难度：进阶动手：20 分钟成本：免费

① Claude Code：用 Hooks 把格式化变成确定性动作

环境：支持 Hooks 的 Claude Code、Node.js 项目、jq 和项目内 Prettier。适用场景：每次 Claude 修改 JavaScript、TypeScript、JSON 或 Markdown 后，都必须按统一规则格式化，而不是靠模型“记得做”。

先在项目根目录安装 Prettier：

npm install --save-dev prettier

再创建或编辑项目级 .claude/settings.json：

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.file_path' | xargs npx prettier --write"
          }
        ]
      }
    ]
  }
}

在 Claude Code 中输入 /hooks，确认 PostToolUse 已注册，然后复制这段测试提示词：

请在当前项目新建 hooks-demo.js，写一个包含单引号、缺少分号且缩进不统一的两行 JavaScript 示例。完成后不要手动运行格式化命令，只告诉我文件最终内容。

验证方法：文件最终格式应符合项目 Prettier 配置。常见坑：Windows/Git-Bash 也要能调用 jq；已有 hooks 时只合并新事件，不能覆盖整个对象；格式化不能代替测试。

什么情况下不该用：仓库没有统一格式规则，或格式化会大面积改动历史文件时，先不要自动启用。

参考：Claude Code 官方 Hooks 指南

Hermes Agent 系列｜第 2 期难度：进阶动手：15 分钟成本：按子代理调用量

② Hermes Agent：三路并行调研，只让摘要回到主上下文

环境：支持 delegate_task 的 Hermes Agent，父代理已启用网页或文件工具。Hermes 子代理拥有隔离会话、终端和工具上下文，中间工具调用不会灌进父代理，只有最终摘要返回。

在 Hermes 对话中直接复制：

请把下面三项调研并行委派给三个独立子代理，全部完成后再综合：
1. 核验最近 36 小时 OpenAI、Anthropic、Google 的官方模型或产品更新；
2. 核验最近 36 小时 NVIDIA、AMD、Intel 的 AI 芯片与数据中心更新；
3. 核验最近 36 小时全球 AI 融资、并购与监管更新。

每个子代理必须：
- 优先打开官方公告、监管文件或论文原文；
- 输出 3—5 条，包含中文标题、发布日期、原始链接、可信度；
- 不得把搜索摘要当成事实；找不到一手来源时降级为媒体报道；
- 不修改文件，不发送消息，不执行系统维护。

父代理最后负责去重，按“正式信息／媒体报道／未经证实”分层，
并指出三路结果之间的共同主线。

delegate_task(tasks=[
  {"goal":"核验头部模型公司更新","context":"最近36小时；只用可打开来源；返回中文结构化摘要"},

验证方法：应收到三份独立结果，再由父代理输出去重综合稿；中间网页材料不应整段进入主上下文。常见坑：子代理不知道主对话前文，必须在 context 中写清时间、路径、输出格式和禁区；可能修改同一文件的任务不要并行。

什么情况下不该用：只有一个简单问题，或三项任务存在严格先后依赖时，串行更可靠。

③ Claude 模型：用提示缓存降低重复长上下文成本

环境：Python 3.9+、Anthropic Python SDK、Claude API 密钥和账户当前可用模型名。提示缓存适合固定规则或长资料反复复用、只有最后问题变化的任务。

python -m pip install -U anthropic
export ANTHROPIC_API_KEY="你的密钥由安全存储注入"
export CLAUDE_MODEL="你的账户当前可用模型名"

保存为 cache_demo.py：

import os
from anthropic import Anthropic

client = Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
model = os.environ["CLAUDE_MODEL"]

long_reference = ("公司客服规则：只能根据给定资料回答；不知道就明确说不知道；"
                  "不得编造价格、库存、退款时限。\n") * 200
system = [{
    "type": "text",
    "text": long_reference,
    "cache_control": {"type": "ephemeral"}
}]

def ask(question):
    response = client.messages.create(
        model=model,
        max_tokens=300,
        system=system,
        messages=[{"role": "user", "content": question}]
    )
    print(response.content[0].text)
    print("缓存写入输入：", getattr(response.usage, "cache_creation_input_tokens", 0))
    print("缓存命中输入：", getattr(response.usage, "cache_read_input_tokens", 0))

ask("请用三句话概括客服回答边界。")
ask("遇到资料未写明的退款时限，应该怎么回答？")
python cache_demo.py

预期结果：第一次调用通常出现缓存写入 token；第二次在缓存有效且前缀完全一致时出现缓存命中 token。常见坑：稳定内容放前面、变化问题放后面；改动缓存断点前的文字、工具定义或顺序会降低命中率；短提示可能达不到最小可缓存长度；不要复用含敏感用户数据的缓存前缀。

什么情况下不该用：每次系统提示、工具列表和资料都大幅变化，或请求很少重复时，收益有限。

参考：Anthropic 官方提示缓存文档
