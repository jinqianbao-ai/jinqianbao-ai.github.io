今天的核心变化是：模型、协作入口、执行框架、人才和数据中心正在被打包成一套系统。先读“今日主线”看懂格局，再按分类阅读 10 条要闻；可信度标签表示证据强弱。

卷首语

本期帮助读者看懂一条主线：AI 竞争的价值中心正在从“谁有更强的单一模型”，移动到“谁能把模型接入真实协作入口、配好执行框架、掌握训练与推理资产，并为全过程保留审计证据”。阅读时先看“今日主线”理解格局变化，再按分类浏览 10 条“今日要闻”；“正式信息、媒体报道、行业风声”表示证据强弱，不代表新闻价值高低。

过去一天，DeepSeek 为 V4-Flash 增加实验性视觉理解，GitHub 把 Copilot 云端智能体带进 Microsoft Teams，英伟达则被曝同时购买模型许可、吸纳人才并投资数据中心开发商。研究侧也在围绕同一问题收敛：工具能力要专门训练，执行框架可以单独优化，高风险机器人必须先获得证据再行动。模型仍然重要，但决定最终效果的已越来越是模型之外的“执行层”。

今日主线：模型能力、协作入口与基础设施被打包成同一套执行系统

重点一：DeepSeek 发布实验性视觉模型，补齐多模态智能体入口

正式信息｜已确认

DeepSeek 8 月 21 日在 API 更新日志中上线 DeepSeek-V4-Flash-Vision-Exp，这是面向视觉理解的实验模型，可通过 API 指定模型名称调用。官方称其纯文本代理、推理和知识能力与 V4-Flash 大体相当，在需要视觉理解的智能体评测上有明显提升；所有跑分均为厂商自报，尚待第三方复现。

与主线的关系： 这不是单纯增加“看图”功能，而是让编码、网页操作、图表分析和视频上下文进入同一代理循环。模型入口从文本扩展到视觉后，执行框架要同时处理附件、工具调用、状态恢复和证据追踪。

1. DeepSeek-V4-Flash-Vision-Exp 上线，视觉代理能力进入实验阶段

正式信息｜已确认

DeepSeek 新模型支持视觉理解，官方给出的评测覆盖 Terminal Bench、NL2Repo、DeepSWE、图表理解和多项代理基准。官方特别说明，纯文本能力与正式版 V4-Flash 接近，而视觉代理任务出现显著增益；模型名称中的 Exp 表明它仍是实验版本，不宜未经回归测试就替换生产模型。

该发布还透露出新的产品路线：厂商不再把多模态只做成聊天界面的识图功能，而是把视觉信号直接接入代码、搜索、自动化和工具调用。对开发者而言，真正需要验证的是图片或视频输入能否稳定转成正确动作，而不只是回答是否流畅。

为什么重要： 多模态代理将扩大可自动化任务范围，也会增加输入体积、隐私、提示注入和错误动作风险。实验模型应采用独立配额、可撤销权限和生产回退线路。

2. GitHub Copilot 在 Teams 中开放多人共同指挥云端智能体

正式信息｜已确认

GitHub Copilot 的 Teams 集成允许多人在同一个聊天上下文中观察调查过程、追加资料并调整任务，智能体随后在安全云沙箱中异步工作。任务产物还可继续在终端、GitHub Copilot 应用或集成开发环境中处理，形成从会议到代码的跨端接力。

公开预览面向付费 Copilot 计划，云端智能体会消耗 AI 积分，云沙箱另行计费；组织可以设置用量预算。仓库写权限仍是触发修改的前提，并可对集成身份创建的拉取请求增加额外人工审批。

为什么重要： 团队协作入口会成为智能体分发的新战场，但“所有人都能说话”不等于“所有人都能改代码”。组织必须把聊天参与权、仓库写权限、合并批准和费用预算分开治理。

6. OpenAI 成立 Strategic Futures 团队，把“权力集中”列为长期 AI 风险

正式信息｜已确认

OpenAI 推出 AI Futures（AI 未来）博客与 Strategic Futures（战略未来）团队，研究变革性 AI 出现后，社会如何保留个人权利与行动能力。首篇文章把权力集中称为长期最严重、最难处理的风险之一，并提出高风险行动应能追溯到负责任的人或人类控制组织，同时强调隐私和匿名表达不能被一并牺牲。

为什么重要： OpenAI 的安全讨论从模型能力、网络攻击和生物风险，进一步扩展到国家、公司和个人之间的权力结构。未来治理争论可能同时围绕“谁能使用 AI”和“谁对高风险动作负责”展开。

7. AI4AI-Bench 测试“让 AI 改进训练算法”，最佳系统仍只走完不足五分之一路程

信息分层：正式信息｜论文原文可核验

AI4AI-Bench 提供 10 个冻结研究仓库，覆盖 10 类训练算法，要求智能体在单张 B300 上用 4 小时改写训练算法，再从头运行最多 12 小时并由隐藏评估器评分。作者测试 6 套系统的 29 种配置，平均标准化分数为 0.166，最佳为 0.250；作者解释，这意味着即使最强系统也只弥合了原始算法到任务最优值之间不到五分之一的差距。

研究发现，很多提交根本没有改变模型如何学习；真正修改训练算法的少数方案表现更好。增加推理投入主要提高了系统“敢于动训练算法”的比例，而不是自动保证成功。

为什么重要： “递归自我改进”常被抽象讨论，这套基准把问题落到可重复实验：AI 能否真正设计更好的训练算法，而不只是调参数或堆数据。当前结果更像能力萌芽，而非自我改进已经失控。

8. MidTool：工具使用不能只靠后训练，模型中期训练也需要真实 API 与 MCP 工作流

信息分层：正式信息｜论文与数据入口可核验

MidTool 提出面向智能体工具使用的中期训练数据构建流程，把网页、PDF、代码、真实工具 API、MCP 技能和文档工作流组合成训练语料。作者用 MidTool-Mix 对 Qwen3-4B-Base 与 Qwen3-8B-Base 进行中期训练，再接监督微调和强化学习，报告称在 BFCL、tau2-Bench 与 MCP Universe 上持续优于对照方案。

论文强调，模型需要专门学习识别工具用途、从上下文填写参数、组合调用流程，以及在信息不完整时恢复，而不能把这些能力全部留给后训练阶段临时补齐。

为什么重要： 工具调用正从“提示词技巧”变成基础模型训练目标。未来代理模型的差异可能更多来自训练数据是否覆盖真实工具约束，而不是只看通用问答跑分。

9. Task-CoEvolve 把智能体执行框架优化成本降低约 80%

信息分层：正式信息｜论文原文可核验

Task-CoEvolve 研究的不是更新模型权重，而是反复改写 harness（智能体执行框架）代码，使同一模型在验证任务上表现更好。传统方法每轮都跑完整验证集，成本很高；新方法优先抽取候选框架表现分歧最大的任务，并用采样概率估计全量得分。

作者在在线文本分类和 Terminal-Bench 2.1 上报告，Task-CoEvolve 在减少约 80% 评测次数的同时，最终性能可接近完整验证集搜索。代码仓库已给出，但论文结果仍需第三方复现。

为什么重要： 当模型能力接近时，执行框架可以成为单独优化的资产。降低框架搜索成本，会让更多团队在不训练新模型的情况下提升智能体效果，也会提高对验证集污染和过拟合的警惕。

10. 机器人“证据门控”研究：找不到目标物体时，先探索或停手，而不是凭常识硬做

信息分层：正式信息｜论文原文可核验

EAFG（证据获取与可行性门控）框架面向部分可观测环境中的长流程机器人任务。视觉语言模型先提出探索子目标，任务与运动规划器执行并收集视觉证据，然后系统决定继续规划、进一步探索或停止；在需要的物体实际不存在时，框架会减少反复尝试和错误操作。

import json

③ Claude 模型系列第 14 期：把真实词元计数接入 RPM、ITPM、OTPM 三重预算队列

难度：高级｜预计动手时间：35 分钟｜成本：词元计数不生成回答，正式请求按模型计费｜环境：Python 3.9+ 标准库、Claude API｜前置：设置 ANTHROPIC_API_KEY、CLAUDE_MODEL 和账号实际限额

适用场景： 上一期已经用 Count Tokens API 拦截超大输入。本期在批量请求前同时控制 RPM（每分钟请求数）、ITPM（每分钟输入词元）和 OTPM（每分钟输出词元），避免短时突发触发 429。Claude 官方说明限流采用持续补充的令牌桶机制，429 通常会返回 retry-after。

把下面代码保存为 claude_rate_queue.py：

展开完整可复制代码／命令
#!/usr/bin/env python3
"""Claude 批量队列：先真实计数，再按 RPM/ITPM/OTPM 令牌桶排队。"""
import json
import os
import sys
import time
import urllib.error
import urllib.request

API_KEY = os.environ["ANTHROPIC_API_KEY"]
MODEL = os.environ["CLAUDE_MODEL"]
RPM = int(os.getenv("CLAUDE_RPM", "30"))
ITPM = int(os.getenv("CLAUDE_ITPM", "50000"))
OTPM = int(os.getenv("CLAUDE_OTPM", "10000"))
MAX_OUTPUT = int(os.getenv("CLAUDE_MAX_OUTPUT", "800"))
VERSION = "2023-06-01"

class Bucket:
    def __init__(self, capacity: int):
        self.capacity = float(capacity)
        self.tokens = float(capacity)
        self.rate = float(capacity) / 60.0
        self.updated = time.monotonic()

    def wait_for(self, amount: int):
        if amount > self.capacity:
            raise SystemExit(f"单个任务需要 {amount}，超过该分钟桶容量 {int(self.capacity)}")
        while True:
            now = time.monotonic()
            self.tokens = min(self.capacity, self.tokens + (now - self.updated) * self.rate)
            self.updated = now
            if self.tokens >= amount:
                self.tokens -= amount
                return
            time.sleep(max(0.05, (amount - self.tokens) / self.rate))

requests_bucket = Bucket(RPM)
input_bucket = Bucket(ITPM)
output_bucket = Bucket(OTPM)

def post(path: str, body: dict):
    req = urllib.request.Request(
        "https://api.anthropic.com" + path,
        data=json.dumps(body, ensure_ascii=False).encode("utf-8"),
        headers={
            "x-api-key": API_KEY,
            "anthropic-version": VERSION,
            "content-type": "application/json",
        },
        method="POST",
    )
    try:
        with urllib.request.urlopen(req, timeout=180) as resp:
            return json.loads(resp.read().decode("utf-8")), dict(resp.headers)
    except urllib.error.HTTPError as exc:
        retry_after = exc.headers.get("retry-after")
        detail = exc.read().decode("utf-8", "replace")
        if exc.code == 429 and retry_after:
            time.sleep(float(retry_after))
            return post(path, body)
        raise SystemExit(f"请求失败，状态码 {exc.code}；请检查密钥、额度或请求格式。详情：{detail}")

def run_job(text: str, number: int):
    body = {"model": MODEL, "messages": [{"role": "user", "content": text}]}
    count, _ = post("/v1/messages/count_tokens", body)
    input_tokens = int(count["input_tokens"])

    # 计数请求也占 RPM；正式生成前为请求、输入和最大输出预留预算。
    requests_bucket.wait_for(1)
    input_bucket.wait_for(input_tokens)
    output_bucket.wait_for(MAX_OUTPUT)

    result, headers = post("/v1/messages", {**body, "max_tokens": MAX_OUTPUT})
    answer = "".join(block.get("text", "") for block in result.get("content", []))
    actual_output = int(result.get("usage", {}).get("output_tokens", 0))
    request_id = headers.get("request-id", "未返回")
    print(json.dumps({
        "任务": number,
        "输入词元": input_tokens,
        "输出词元": actual_output,
        "请求ID": request_id,
        "回答": answer,
    }, ensure_ascii=False))

for index, line in enumerate(sys.stdin, 1):
    if line.strip():
        run_job(line.strip(), index)

什么情况下不该用： 需要数百并发、持久队列、跨机器协调或严格一次性语义时，不要依赖单进程脚本，应使用数据库队列和集中式限流服务。
