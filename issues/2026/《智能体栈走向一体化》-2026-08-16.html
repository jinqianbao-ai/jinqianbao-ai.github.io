重点一：DeepSeek 同时补齐 V4 Pro 与开源 Harness

信息分层：正式信息｜已确认

DeepSeek API 平台已显示 V4 Pro 正式版上线，强调更强的智能体能力，并支持 Responses API 与 Codex 集成。与此同时，DeepSeek Harness（智能体运行框架，简称 DSH）以 MIT 协议公开，采用“一切皆插件”的架构；官方仓库明确标注当前仍是开发者预览，未来会发生破坏兼容性的变化。

为什么重要： DeepSeek 正从“提供便宜模型接口”扩展到“提供模型 + 智能体运行时 + 插件生态”。这会直接影响开发者对 Claude Code、Grok Build、OpenAI Codex 与其他代理框架的选型。

重点二：腾讯 QQ Bot 把 DeepSeek Harness 接到真实社交入口

信息分层：媒体报道｜待官方完整确认

腾讯 QQ 官方账号 8 月 15 日宣布 QQ Bot 接入 DeepSeek Harness 官方插件。公开报道显示，私聊与群聊可分别保存独立记忆，机器人重启后可恢复会话，并支持在保留上下文的情况下切换模型；群聊还可设置“仅被 @ 时响应”，以减少刷屏。

为什么重要： 智能体框架只有进入现成的用户入口，才能形成持续调用、长期记忆和插件消费。DeepSeek Harness 发布约两天就进入 QQ Bot，说明国内模型厂商与超级应用之间的分发速度正在加快。

① Claude Code 系列第 9 期：用 TaskCompleted Hook 把测试变成完成门禁

  • 难度： 进阶｜动手： 20—30 分钟｜成本： 配置免费，Claude Code 调用按订阅或 API 计费
  • 环境： Claude Code 当前官方版；项目根目录可运行测试命令；承接第 8 期 Agent Teams
  • 场景： 防止队友在测试失败时把共享任务标记为完成。官方文档确认 TaskCompleted 在任务准备完成时触发，退出码 2 会阻止完成并把标准错误反馈给代理。

在项目根目录创建 .claude/hooks/verify-task.sh：

#!/usr/bin/env bash
set -u

# Hook 从标准输入收到任务 JSON；先保存，方便脚本读取任务标题。
payload="$(cat)"
subject="$(printf '%s' "$payload" | python -c 'import json,sys; print(json.load(sys.stdin).get("task_subject", "未命名任务"))')"

# 请把下一行替换成项目真实的最小测试命令。
if ! npm test -- --runInBand; then
  printf '任务“%s”尚不能完成：测试失败。请修复后重新运行测试。\n' "$subject" >&2
  exit 2
fi

printf '任务“%s”测试通过，允许标记完成。\n' "$subject" >&2
exit 0

赋予执行权限：

chmod +x .claude/hooks/verify-task.sh

在 .claude/settings.json 中加入；已有设置时只合并 hooks 字段：

{
  "hooks": {
    "TaskCompleted": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/verify-task.sh",
            "timeout": 120
          }
        ]
      }
    ]
  }
}

启动 Claude Code 后发送：

请创建一个 Agent Team，把“实现功能”“补测试”“独立验证”拆成有依赖关系的任务。任何队友准备把任务标记为完成前，都必须服从 TaskCompleted Hook；如果 Hook 返回测试失败，不得绕过门禁，不得删除测试，只能修复实现或测试环境后再次申请完成。

成功标志： 测试失败时任务保持未完成，并出现脚本返回的中文原因；测试通过后才允许关闭任务。常见坑： Windows 原生 shell 环境需要把脚本改成可执行的 Python 文件；测试命令过慢会拖住每次完成操作；Hook 不支持 matcher，会在每个任务完成时触发。不该用： 没有稳定自动化测试、或完成标准主要依赖人工审美判断时，不应把单一测试命令当成唯一门禁。

参考：https://code.claude.com/docs/en/hooks#taskcompleted

② Hermes Agent 系列第 9 期：用独立 reviewer 档案形成退回与复审闭环

  • 难度： 进阶｜动手： 15—25 分钟｜成本： 配置免费，模型调用计费
  • 环境： Hermes Agent 当前官方版；已有第 8 期 orchestrator 档案与 Kanban 看板
  • 场景： 将“实现者”和“审查者”分权。reviewer 只通过 Kanban 接收待审任务、提交结论或退回修改，不直接替实现者改稿。

创建审查档案：

hermes profile create reviewer --description "只负责核验证据、测试、权限与交付标准；发现问题通过 Kanban 退回，不直接修改实现。"

启动仅含 Kanban 工具集的审查会话：

hermes -p reviewer chat --toolsets kanban

进入会话后完整发送：

你是独立 reviewer。只处理分配给 reviewer、处于待审或复审状态的 Kanban 任务。

审查顺序固定为：
1. 核对任务描述、依赖与完成标准；
2. 核对执行者提交的文件路径、测试结果、原始链接和风险说明；
3. 缺少证据、测试失败、权限越界或结果不可复现时，使用看板的退回修改动作，并逐条写清问题；
4. 不得亲自修改交付物，不得把“我认为应该没问题”当证据；
5. 执行者重新提交后，从头复审，不沿用旧结论；
6. 全部通过时提交批准结论，列出已核验项目、残余风险和人工发布前需要确认的事项；
7. 最后只汇报任务ID、审查状态、证据和残余风险。

在另一个终端观察审查状态：

hermes kanban list
hermes kanban watch --kinds review_requested,changes_requested,completed,blocked

成功标志： reviewer 只能看到 Kanban 工具；不合格任务进入退回修改状态，重新提交后产生新的复审记录；实现者与审查者的动作在任务历史中分离。常见坑： reviewer 若拥有终端与文件工具，容易越权“顺手修复”；任务没有明确完成标准时，审查会退化为主观判断；短任务不适合引入完整复审链。不该用： 一次性低风险问答或没有持久状态的短任务，直接人工检查更省成本。

③ Claude 模型系列第 9 期：主备供应商切换时记录请求 ID，避免盲目重试

  • 难度： 进阶｜动手： 30—45 分钟｜成本： 脚本免费；API 按实际词元计费
  • 环境： Python 3.10+；安装 anthropic 当前稳定版；设置 ANTHROPIC_API_KEY；备用线路通过 ANTHROPIC_FALLBACK_BASE_URL 与 ANTHROPIC_FALLBACK_API_KEY 配置
  • 场景： 承接第 8 期风险路由与费用熔断，在临时网络错误、429、5xx 或 529 时切到备用兼容线路，并把 Anthropic request-id 写入账本。官方说明每个响应都有唯一请求 ID，官方 SDK默认会对瞬时错误重试两次；本例关闭 SDK 内部重试，避免与外层切换叠加。

安装依赖：

python -m pip install "anthropic>=0.60,<1"

保存为 claude_failover.py：

import json, os, sys, time, uuid
from datetime import datetime, timezone
from pathlib import Path

import anthropic

MODEL = os.getenv("CLAUDE_MODEL", "claude-sonnet-5")
LEDGER = Path(os.getenv("CLAUDE_FAILOVER_LEDGER", "claude_failover.jsonl"))

providers = [
    {
        "name": "主线路",
        "api_key": os.environ["ANTHROPIC_API_KEY"],
        "base_url": os.getenv("ANTHROPIC_BASE_URL", "https://api.anthropic.com"),
    }
]
if os.getenv("ANTHROPIC_FALLBACK_API_KEY") and os.getenv("ANTHROPIC_FALLBACK_BASE_URL"):
    providers.append({
        "name": "备用线路",
        "api_key": os.environ["ANTHROPIC_FALLBACK_API_KEY"],
        "base_url": os.environ["ANTHROPIC_FALLBACK_BASE_URL"],
    })

RETRYABLE = (
    anthropic.RateLimitError,
    anthropic.InternalServerError,
    anthropic.APIConnectionError,
    anthropic.APITimeoutError,
)

def log(row):
    with LEDGER.open("a", encoding="utf-8") as f:
        f.write(json.dumps(row, ensure_ascii=False) + "\n")

def ask(prompt):
    operation_id = str(uuid.uuid4())
    last_error = None
    for provider in providers:
        client = anthropic.Anthropic(
            api_key=provider["api_key"],
            base_url=provider["base_url"],
            max_retries=0,  # 外层负责切换，避免双重重试
            timeout=90,
        )
        try:
            message = client.messages.create(
                model=MODEL,
                max_tokens=800,
                messages=[{"role": "user", "content": prompt}],
            )
            request_id = getattr(message, "_request_id", None)
            row = {
                "time": datetime.now(timezone.utc).isoformat(),
                "operation_id": operation_id,
                "provider": provider["name"],
                "request_id": request_id,
                "model": MODEL,
                "input_tokens": message.usage.input_tokens,
                "output_tokens": message.usage.output_tokens,
                "status": "success",
            }
            log(row)
            text = "".join(block.text for block in message.content if block.type == "text")
            return row, text
        except RETRYABLE as exc:
            last_error = exc
            request_id = getattr(exc, "request_id", None)
            log({
                "time": datetime.now(timezone.utc).isoformat(),
                "operation_id": operation_id,
                "provider": provider["name"],
                "request_id": request_id,
                "status": "retryable_error",
                "error_type": type(exc).__name__,
            })
            time.sleep(1)
            continue
        except anthropic.APIStatusError as exc:
            # 400、401、403、404 等通常不是换线路能解决的问题，立即停止。
            log({
                "time": datetime.now(timezone.utc).isoformat(),
                "operation_id": operation_id,
                "provider": provider["name"],
                "request_id": getattr(exc, "request_id", None),
                "status": "fatal_error",
                "http_status": exc.status_code,
            })
            raise
    raise RuntimeError(f"主备线路均失败：{type(last_error).__name__}")

if __name__ == "__main__":
    prompt = " ".join(sys.argv[1:]) or "用三点总结主备模型切换的风险。"
    meta, answer = ask(prompt)
    print(json.dumps(meta, ensure_ascii=False, indent=2))
    print(answer)
