今日主线：企业级 AI 开始同时购买能力、隐私与安全证据

重点一：OpenAI 把前沿模型纳入零数据保留承诺

信息分层：正式信息｜已确认

OpenAI 8 月 19 日宣布，符合条件的 API 客户可对前沿模型使用 Zero Data Retention（零数据保留，简称 ZDR）：请求处理完成后不保留提示词和模型回答，企业数据默认不用于训练，除非客户主动选择加入。客户内容也不会提供给 OpenAI 人员审阅。

为什么重要： 前沿模型此前常因安全监控需要而要求更长的数据保留，敏感行业因而必须在能力和隐私之间二选一。ZDR 扩展到前沿模型，意味着隐私承诺正成为模型竞争的核心产品能力。

来源：OpenAI｜发布时间：2026-08-19｜可信度：高
https://openai.com/index/our-commitment-to-zero-data-retention/

重点二：私密安全处理尝试跨会话识别风险但不暴露原文

信息分层：正式信息｜已确认

OpenAI 同时预告 Private Safety Processing（私密安全处理）：自动系统可跨相关交互识别长期滥用模式，但只向 OpenAI 返回有限的风险类别信号，不向人员暴露底层提示词或回答。客户内容可留在客户自有基础设施，也可存放在 OpenAI 侧并使用客户控制的密钥加密；该方案正与早期客户测试，计划 9 月开始推出并发布技术白皮书。

为什么重要： 智能体任务的风险可能跨多轮、跨账号逐步形成，单次请求过滤不足；但集中留存所有原文又会制造新的隐私风险。能否同时实现长周期监控和内容不可见，将决定金融、医疗和专有研发能否采用更强模型。

https://openai.com/index/our-commitment-to-zero-data-retention/

信息分层：正式信息｜已确认

为什么重要： 模型公司今后的真实竞争力，不只取决于芯片数量，还取决于电力、冷却、许可、隐私和风险监控能否共同扩展。

3. Cerebras 发布 CS-4，主打晶圆级推理与模块化机架

信息分层：正式信息｜已确认

CS-4 采用三颗 WSE-3 Turbo 晶圆级处理器、低至 2 微秒的晶圆间连接、模块化 Nexus 机架，并原生支持把预填充与解码分配给不同硬件。Cerebras 宣称部分模型推理速度最高可达 GPU 系统的 30 倍、相对 CS-3 每瓦吞吐最高提升 10 倍，首批设备本季度发货。

9. Co-RL 用多模型同伴奖励推进无标签推理训练

信息分层：正式信息｜论文原文已核验

Co-RL（协作式强化学习）让多个参数不共享的模型同时训练，并用同伴输出形成奖励；作者通过不同模型家族、规模与改写样本增加群体多样性，以减少相关性错误和自我强化崩塌。论文报告七个文本基准平均提升 3.0%—8.6%，四个多模态基准提升 2.3%—7.2%，且不使用真实标签。

为什么重要： 当高质量可验证标签越来越昂贵，多模型之间的差异可被用作训练信号。不过“同伴共识”仍可能共同犯错，结果为作者报告，需独立复现并检查计算成本。

10. DeAR 探索去中心化多智能体推理

信息分层：正式信息｜论文原文已核验

DeAR（去中心化智能体推理）不设置单一中央调度器，而让代理根据查询动态确定能力、沿“思维地图”选择同伴交互，并在发现错误后更新协作拓扑。作者称其在九个多模态推理与文本问答基准上优于近期基线，但摘要未给出统一幅度，代码链接目前仍写为录用后开放。

为什么重要： 中央调度器容易形成瓶颈和静态角色错配，点对点协作可能提升复杂任务的适应性；但通信成本、循环争论和责任追踪会变得更难，现阶段证据强度低于已有代码的研究。

① Claude Code 系列第 12 期：把工具失败与 API 终止写入分类账

  • 难度： 进阶
  • 预计动手时间： 25—35 分钟
  • 成本： 配置与脚本免费；Claude Code 按订阅或 API 计费
  • 环境版本： Claude Code 当前官方 Hooks 文档；Python 3.9+
  • 承接关系： 第 11 期已记录 SubagentStart／SubagentStop；本期继续记录 PostToolUseFailure 与 StopFailure，区分“工具失败”和“整轮因 API 错误终止”。

创建 .claude/hooks/failure-ledger.py：

#!/usr/bin/env python3
import json
import sys
from datetime import datetime, timezone
from pathlib import Path

payload = json.load(sys.stdin)
root = Path(payload.get("cwd", "."))
out = root / "artifacts"
out.mkdir(parents=True, exist_ok=True)

event = payload.get("hook_event_name", "unknown")
record = {
    "time_utc": datetime.now(timezone.utc).isoformat(),
    "event": event,
    "session_id": payload.get("session_id"),
    "tool_name": payload.get("tool_name"),
    "tool_use_id": payload.get("tool_use_id"),
    "error": payload.get("error"),
    "last_assistant_message": payload.get("last_assistant_message"),
}

with (out / "failure-ledger.jsonl").open("a", encoding="utf-8") as f:
    f.write(json.dumps(record, ensure_ascii=False) + "\n")

# 只记录，不阻断 Claude Code 后续行为。
raise SystemExit(0)

在 .claude/settings.json 写入完整配置：

{
  "hooks": {
    "PostToolUseFailure": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "python \"$CLAUDE_PROJECT_DIR/.claude/hooks/failure-ledger.py\"",
            "timeout": 20
          }
        ]
      }
    ],
    "StopFailure": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "python \"$CLAUDE_PROJECT_DIR/.claude/hooks/failure-ledger.py\"",
            "timeout": 20
          }
        ]
      }
    ]
  }
}

可直接复制给 Claude Code 的提示词：

请执行一次只读检查并保留现有 Hooks。若工具失败，不要把它概括成“任务失败”：先读取 artifacts/failure-ledger.jsonl，按“工具名、错误信息、是否可重试、是否需要权限、是否影响最终结论”分类。若出现 StopFailure，明确说明这是整轮因 API 错误结束，不能自动推断任何工具已经回滚。最后给出最小重试方案，不得重复执行有副作用的命令。

验证方法： 在 Claude Code 的 /hooks 中确认两个事件已注册；发生工具错误后，artifacts/failure-ledger.jsonl 应新增 PostToolUseFailure；若整轮因 API 错误结束，则应出现 StopFailure。
常见坑： 两个事件的字段并不完全相同，因此脚本用 get 容忍缺失；日志可能包含敏感错误文本，应限制访问；Hook 成功只代表记录成功，不代表业务重试安全。
什么情况下不该用： 项目不允许在本地保存错误内容，或错误信息可能包含密钥、个人数据且没有脱敏措施时，不应直接落盘。
参考： https://code.claude.com/docs/en/hooks

② Hermes Agent 系列第 12 期：用 Git worktree 隔离研究、写作与复核

  • 难度： 进阶
  • 预计动手时间： 25—40 分钟
  • 成本： 免费；多会话会增加模型调用费和少量磁盘占用
  • 环境版本： Hermes Agent 当前官方 Git Worktrees 文档；Git 2.20+
  • 承接关系： 第 11 期已把研究、写作、复核分成独立 worker lanes；本期把每条泳道放进独立分支和目录，避免互相覆盖文件。

在项目根目录创建三棵工作树：

git fetch --all --prune
git worktree add ../ai-research -b daily/research
git worktree add ../ai-writing -b daily/writing
git worktree add ../ai-review -b daily/review

分别启动 Hermes：

cd ../ai-research && hermes
cd ../ai-writing && hermes
cd ../ai-review && hermes

也可以让单次 Hermes 会话自动创建隔离工作树：

cd /path/to/your/repo
hermes -w -z "只在隔离分支完成任务；提交前运行测试并输出变更摘要。"

给三条泳道使用以下交接提示词：

你当前位于独立 Git worktree。research 分支只提交来源与证据；writing 分支只根据已合并的研究提交撰写正文；review 分支只做事实、测试和差异审查，不直接把未经批准的修改合并到主分支。每次交接必须提供提交哈希、变更文件、验证命令和未解决风险。发现上游分支未合并时立即停止，不得从其他工作树直接复制未提交文件。

推荐的人工合并顺序：

cd /path/to/your/repo
git merge --no-ff daily/research
git merge --no-ff daily/writing
git merge --no-ff daily/review

验证方法： git worktree list 应显示三个独立目录和分支；任何一个工作树中的未提交修改不应出现在另两个目录；每次合并前检查 git status 和差异。
常见坑： 同一分支不能同时被多个工作树检出；写作分支必须基于已合并的研究证据，否则会产生隐形版本差；git worktree remove 默认拒绝删除有未提交改动的目录，这是保护机制。
什么情况下不该用： 非 Git 项目、只有一个小文件的短任务，或团队没有明确合并责任人时，不应增加多工作树复杂度。
参考： https://hermes-agent.nousresearch.com/docs/user-guide/git-worktrees

③ Claude 模型系列第 12 期：用并发信号量与分钟词元预算提前削峰

  • 难度： 高级
  • 预计动手时间： 35—50 分钟
  • 成本： 示例代码免费；Claude API 按实际词元计费
  • 环境版本： Python 3.10+；anthropic>=0.60,<1
  • 前置条件： 设置 ANTHROPIC_API_KEY；模型名通过 CLAUDE_MODEL 环境变量配置
  • 承接关系： 第 11 期区分 429、529 与网络超时；本期在请求发出前限制并发和每分钟预计输入词元，减少触发限流后再重试的浪费。

安装依赖：

python -m pip install "anthropic>=0.60,<1"

保存为 claude_budget_gate.py：

import asyncio
import os
import time
from collections import deque
import anthropic

MODEL = os.getenv("CLAUDE_MODEL", "claude-sonnet-5")
MAX_CONCURRENT = int(os.getenv("CLAUDE_MAX_CONCURRENT", "3"))
INPUT_TOKENS_PER_MINUTE = int(os.getenv("CLAUDE_ITPM_BUDGET", "60000"))

client = anthropic.AsyncAnthropic(
    api_key=os.environ["ANTHROPIC_API_KEY"],
    max_retries=2,
    timeout=60,
)
semaphore = asyncio.Semaphore(MAX_CONCURRENT)
usage_window = deque()  # 保存最近 60 秒的预计输入词元
lock = asyncio.Lock()


async def reserve_tokens(estimated_tokens: int) -> None:
    while True:
        async with lock:
            now = time.monotonic()
            while usage_window and now - usage_window[0][0] >= 60:
                usage_window.popleft()
            used = sum(tokens for _, tokens in usage_window)
            if used + estimated_tokens <= INPUT_TOKENS_PER_MINUTE:
                usage_window.append((now, estimated_tokens))
                return
            wait = max(0.2, 60 - (now - usage_window[0][0]))
        await asyncio.sleep(wait)


async def ask(prompt: str) -> str:
    # 粗略估算英文约 4 字符一个词元；中文应预留更大安全余量。
    estimated = max(32, len(prompt) // 2)
    await reserve_tokens(estimated)
    async with semaphore:
        message = await client.messages.create(
            model=MODEL,
            max_tokens=300,
            messages=[{"role": "user", "content": prompt}],
        )
        return "".join(block.text for block in message.content if block.type == "text")


async def main() -> None:
    prompts = [
        "用两句话解释令牌桶限流。",
        "用两句话解释为什么要限制客户端并发。",
        "用两句话解释提示缓存如何提高有效吞吐。",
        "用两句话解释为什么不能无限重试 429。",
        "用两句话解释输入词元与输出词元预算的区别。",
    ]
    results = await asyncio.gather(*(ask(p) for p in prompts))
    for index, result in enumerate(results, 1):
        print(f"任务 {index}：{result}\n")


if __name__ == "__main__":
    asyncio.run(main())

运行：

export ANTHROPIC_API_KEY="你的环境变量密钥"
export CLAUDE_MODEL="claude-sonnet-5"
export CLAUDE_MAX_CONCURRENT="3"
export CLAUDE_ITPM_BUDGET="60000"
python claude_budget_gate.py

成功标志： 五个任务最终都有中文输出；并发数永远不超过环境变量设置；当预计输入词元达到分钟预算时，新请求会等待而不是立即撞 429。
常见坑： 字符数只能粗略估算词元，生产环境应先调用官方 Count Tokens API；官方限流按 RPM、ITPM、OTPM 分开，本例只演示并发和输入预算；缓存读取词元对多数模型不计入 ITPM，但具体模型仍应查当前文档；企业还应设置月度费用上限。
什么情况下不该用： 请求带不可逆副作用、没有幂等键，或必须严格按照实际词元而非估算词元执行计费控制时，不应直接采用本例。
参考： https://platform.claude.com/docs/en/api/rate-limits
