今日主线

代理正在从“能调用工具”变成“必须被基础设施约束的执行系统”

过去24—36小时，OpenAI把低延迟决策接口和企业级代理部署推向产品化，同时公开训练环境无网隔离、红队和安全案例；NVIDIA则把代理运行时、DPU监控、本地硬件和主权算力放到同一张基础设施图上。科研与企业落地也在同步推进：Anthropic开放生命科学合作，Uber把代理扩展到3万多名员工，机器人评测开始把碰撞、跌倒和动态任务纳入指标。

  • 重点一：安全不再是上线前检查，而是运行时、网络和硬件层的持续约束。
  • 重点二：算力竞争延伸到桌面、本地数据、能源和国家级基础设施。
  • 重点三：企业买的不是一个聊天模型，而是一套能留痕、能回退、能审计的工作系统。

1. OpenAI把“决策接口”做成正式产品

OpenAI 于10月22日宣布 Decisions API（决策接口）正式可用，专门处理分类、路由、继续/重试等边界清晰的小决策。官方称它基于 GPT-6 Luna，在相同任务上最高可比 Responses API 快10倍，并支持文字、图片、原生 JSON、提示词缓存和美国/欧盟推理驻留。

为什么重要：这说明模型竞争正在从“回答得更长”转向“在工作流热路径上更快、更便宜地做出可执行判断”。对于代理系统，低延迟的决策层可能比更大的通用模型更直接地决定单位任务成本。

📚 AI实用教程

三条固定连载并行推进：Claude Code负责终端编码代理，Hermes Agent负责调度与验收，Claude模型系列负责接入、成本与故障控制。教程是可核验的动手材料，不能替代权限审批和人工复核。

Claude Code系列｜第45期：用测试门禁约束代理改动｜难度：进阶

t1

动手时间：20—30分钟｜成本：免费；需要 Claude Code、一个可运行测试的代码仓库｜环境：见本篇前置条件

本期把第44期的提交前Hooks继续推进：让编码代理的改动必须经过真实测试，失败时保留失败状态，不以“看起来合理”代替验证。适合希望让 Claude Code 自动修改代码、但不愿把未验证改动直接交付的开发者。

操作步骤：

1. 在仓库根目录创建 `.claude/hooks/pre-commit-check.sh`。
2. 粘贴下面完整脚本，并根据项目实际测试入口保留 `npm test` 或 `python -m pytest`。
3. 给脚本执行权限：`chmod +x .claude/hooks/pre-commit-check.sh`。
4. 让 Claude Code 先读测试结果再修改代码；测试失败时要求它修复并重新运行。
5. 以“测试命令退出码为0、关键回归用例通过、差异可审阅”为成功标准。

完整示例：

#!/usr/bin/env bash
set -euo pipefail

# 先检查当前仓库是否存在测试入口，再交给 Claude Code 执行
if [ -f package.json ]; then
  npm test
elif [ -f pyproject.toml ]; then
  python -m pytest
else
  echo "未识别测试入口，请先在项目中定义测试命令" >&2
  exit 1
fi

常见坑：仓库没有统一测试入口、测试依赖未安装、钩子脚本吞掉失败退出码。失败时先恢复真实错误，再补测试，不要把脚本改成永远成功。参考：Claude Code Hooks官方文档。什么情况下不该用这个方法：项目测试本身会修改生产数据或依赖不可控外部服务时，不要直接绑定提交钩子，应先做隔离测试。

Hermes Agent系列｜第45期：让并行调研返回可合并证据｜难度：进阶

t2

动手时间：20—30分钟｜成本：免费；需要支持委派子代理和文件写入的 Hermes Agent｜环境：见本篇前置条件

上一期建立了结构化验收表，本期进一步规定并行子代理的返回契约，让主代理能合并结果而不是拼接多段散文。适合需要同时检索多个公司、产品或论文，又要保持事实与推断分离的任务。

操作步骤：

1. 给每个子代理同一份字段契约。
2. 每个代理只负责一个来源簇或一个主题，不交叉写最终日报。
3. 主代理先检查字段是否完整，再检查URL能否回查，最后才写入正文。
4. 相互独立的检索可以并行；涉及上一项结论的核验必须串行。
5. 任何“来源不足”的结果进入待核验区，不得自动升级为正式信息。

完整示例：

请把本次研究结果整理成严格的验收表：
1. 已确认事实：每条附原始URL和发布时间
2. 媒体报道：列出已确认部分与未确认部分
3. 未经证实线索：只保留可追踪内容，标出证据弱点
4. 不能写入日报的内容：逐条说明原因
5. 最终建议：不超过三条，不能把推断写成事实
不要复制英文段落，不要补写没有来源的数字。

常见坑：子代理重复搜索、把搜索摘要当原文、把推测塞进“结论”字段。失败时保留原始URL和证据缺口，宁可少写一句，也不要补写数字。参考：Hermes Agent官方文档。什么情况下不该用这个方法：需要连续共享同一份实时状态、且每一步依赖前一步输出时，不要强行并行。

Claude模型系列｜第45期：把低延迟决策从通用调用中拆出来｜难度：进阶

t3

动手时间：30—40分钟｜成本：按API实际用量计费；需要OpenAI API账号、Python 3.10+和环境变量｜环境：见本篇前置条件

本期结合 Decisions API 的正式发布，讲清一个成本与延迟原则：分类、路由、继续/重试这类边界清晰的小判断，不必每次调用最重的通用工作流。示例只展示环境变量，不包含真实密钥；模型名和接口参数请以官方开发者文档当前版本为准。

操作步骤：

1. 设置环境变量 `OPENAI_API_KEY`，不要把密钥写进代码或提交到仓库。
2. 安装并锁定当前官方 Python SDK 版本。
3. 先用离线样本测试三种结果：继续、重试、人工。
4. 记录每次请求的延迟、输入Token、结果和人工改判。
5. 当低置信度或结果不在允许集合中时，默认转人工，不要自动执行。

完整示例：

import os
from openai import OpenAI

# 密钥只从环境变量读取，不写进代码
client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])

response = client.responses.create(
    model="gpt-6.1-sol",
    input="请判断：这条工单应当继续、重试还是交给人工？只返回三个选项之一。",
)
print(response.output_text)

常见坑：把示例模型名当成永久版本、未查当前官方接口、把低置信度结果直接用于高风险操作。失败时先查看官方开发者文档和账户权限，再检查环境变量是否存在。参考：OpenAI Decisions API公告。什么情况下不该用这个方法：涉及转账、删除、生产发布或其他不可逆动作时，不能只依赖低成本分类结果，必须增加权限和人工确认。
