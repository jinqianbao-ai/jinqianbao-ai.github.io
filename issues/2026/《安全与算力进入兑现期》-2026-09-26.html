今日主线：安全评估与算力交付同时进入硬约束

过去一天最值得注意的变化，不是又一个排行榜刷新，而是 AI 产业开始被两类现实账单追问：模型由谁、以什么权限独立评估；数据中心承诺能否变成有电、有冷却、有融资、有许可的上线容量。

  • 安全关系：第三方评估正在从发布附录走向持续治理。
  • 基础设施关系：代理成本扩展到 CPU、内存、电网、冷却和债务。
  • 产品关系：模型能力与权限边界被合并成开发者产品。

Claude Code 系列第28期：为高权限工具建立“审批—回滚—审计”最小闭环

难度：进阶｜动手时间：40—60 分钟｜成本：Claude Code、Git、Python 3.11+；按实际用量计费，示例本地免费｜参考：官方文档

适用场景：编码代理要修改配置、运行测试或调用外部工具，但每一步都必须可暂停、可复核、可回滚。

  1. 先在测试仓库确认已有测试命令，不要把生产凭证放进环境。
  2. 用 `PreToolUse` 检查目标文件和危险命令；`.env`、密钥、生产配置默认要求人工确认。
  3. 用 `PostToolUse` 和失败钩子记录工具名、目标、退出码、测试结果和差异文件。
  4. 任务结束时只生成审计报告，不自动提交或推送；人工确认后再合并。
claude -p "请读取当前仓库已有测试命令，设计 Claude Code hooks：修改前阻止 .env、密钥和生产配置；修改后记录工具、目标、退出码和 git diff 文件清单。先不要写入，输出完整配置、失败恢复步骤和需要人工确认的节点。"

claude -p "请审查当前 git diff 并运行已有最小测试，只报告改动文件、测试结果、权限越界风险和回滚步骤；不要提交、推送或修改文件，中文回答。" ```

常见坑：把钩子当成系统级安全边界；审计记录泄露密钥；只记录“成功”而不记录目标和版本。失败时先停止写入，保留差异，再人工检查权限规则。

什么情况下不该用：生产发布、支付、数据库迁移和真实交易不能只依赖代理钩子。

Hermes Agent 系列第28期：并行采集的超时、部分失败与一次性汇总

难度：进阶｜动手时间：35—50 分钟｜成本：Hermes Agent、Python 3.11+、非生产测试目录；模型与网页服务按实际用量计费｜参考：官方文档

适用场景：多个子任务并行查来源，但最终只能生成一份去重、可核验的日报结果。

# hermes_partial_failures.py —— 标准库演示部分失败收口，不连接外部服务
from dataclasses import dataclass, asdict
import json
from pathlib import Path

@dataclass class Result: task_id: str status: str detail: str

results = [ Result("官方公告", "verified", "已打开原网页并记录发布时间"), Result("社区信号", "timeout", "超时，不能写入事实区"), Result("论文", "verified", "已读取摘要与提交记录"), ]

out = Path("hermes_summary.json") if not out.exists(): payload = {"verified": [asdict(x) for x in results if x.status == "verified"], "needs_review": [asdict(x) for x in results if x.status != "verified"]} out.write_text(json.dumps(payload, ensure_ascii=False, indent=2), encoding="utf-8") else: print("已存在汇总，拒绝重复写入") print("已核验：", sum(x.status == "verified" for x in results), "条") print("待复核：", sum(x.status != "verified" for x in results), "条") ```

预期输出是“已核验：2 条、待复核：1 条”。超时结果必须进入待复核区，不能因为任务总数完成就当作成功。主代理收口时还要按 URL 去重，检查每条是否有来源、时间和可信度。

常见坑：超时自动标成成功；子代理直接改主索引；同一个 URL 因重试重复出现。解决办法是结构化返回、一次性汇总、主代理最终计数。

什么情况下不该用：不可逆外部动作不能仅凭“没有结果”自动重试，必须先确认服务端是否已接受请求。

Claude 模型系列第28期：用请求账本做路由、限流与月度成本对账

难度：进阶｜动手时间：40—60 分钟｜成本：Python 3.11+；API 密钥只放环境变量；实际调用按当前官方价格计费｜参考：官方文档

适用场景：同一应用同时使用高能力模型、快速模型和备用线路，需要知道每次请求花了什么、为什么重试。

# claude_ledger.py —— 本地成本账本演示，不发送 API 请求
import csv
from pathlib import Path

rows = [ {"request_id":"req-001", "model":"主模型", "input_tokens":1200, "output_tokens":300, "status":"ok"}, {"request_id":"req-002", "model":"快速模型", "input_tokens":900, "output_tokens":120, "status":"429"}, ] path = Path("claude_request_ledger.csv") with path.open("w", newline="", encoding="utf-8-sig") as f: writer = csv.DictWriter(f, fieldnames=rows[0].keys()) writer.writeheader(); writer.writerows(rows) print("已写入请求账本：", path) print("成功请求：", sum(r["status"] == "ok" for r in rows)) print("限流请求：", sum(r["status"] == "429" for r in rows)) ```

生产接入时记录请求 ID、模型、输入/输出/缓存 token、状态码、重试次数和最终费用；价格和模型名称必须从当前官方文档读取。429、临时服务故障和超时只能有限退避；认证失败、参数错误和政策拒绝不要盲目重试。多 worker 共享分钟额度时必须有全局限流，而不是每个 worker 各算一份预算。

常见坑：把所有失败都重试；备用模型质量不匹配；只记总账不记单请求；把真实密钥写进代码或日志。

什么情况下不该用：医疗、法律、金融交易和高权限决策不能因为成本路由自动降级为未经审查的模型。
