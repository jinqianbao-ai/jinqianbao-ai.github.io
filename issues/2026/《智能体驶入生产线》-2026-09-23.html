今日主线：智能体竞争从模型能力进入生产系统的四道闸门

过去一天的公开信息拼出一幅相互牵制的图景：Microsoft Foundry 把 GPT-6 Astra、Sol、Luna 分成高难度、通用生产和高吞吐三档；GitHub Copilot 同时扩充多家模型并增加工具审批；Intrinsic、NVIDIA、Unity 则把机器人控制、仿真和数字孪生变成更可复用的工程底座。另一边，国际声明与 Anthropic 的事件披露说明，真正的生产化还要过安全评估、权限、能源与责任四道闸门。

📚 AI实用教程

本期为三条固定连载的创刊第25期，主题从“能调用模型”推进到“能把模型、权限、成本和验证放进同一条生产链”。教程区占本报附加内容，命令和代码只使用公开文档可核验的接口；密钥均通过环境变量处理。

① Claude Code 系列第25期：把 MCP 工具分成只读层与写入层

难度：进阶｜动手时间：25—40 分钟｜成本：按 Claude Code 实际用量计费｜环境：Claude Code、Git、一个可回滚的测试仓库｜参考：Claude Code MCP 文档

适用场景：让终端编码代理查询工单、文档或测试数据，但不让它默认拥有发版、删库或支付权限。核心原则是先只读，写入工具单独命名、单独审批。

  1. 在测试仓库中先让代理列出当前 MCP 工具及其用途，不允许修改文件。
  2. 为查询类工具准备只读凭证；写入类工具使用另一套凭证并要求人工确认。
  3. 让代理先生成计划，再审查工具调用清单，最后才执行最小写入。
# 只读分析
claude -p "请检查当前项目可用的 MCP 工具。只列出工具名称、读取的数据范围、可能的副作用和所需审批；不要调用写入工具，不要修改任何文件。输出中文。"

# 生成执行计划
claude -p "请为修复一个登录超时问题生成计划：先读取日志和测试，再提出最小修改，最后列出需要人工确认的写入动作。不要执行写入。输出文件范围、验证命令和回滚方式。"

# 独立复核
claude -p "请只审查上面的计划和 git diff，检查 MCP 工具是否越权、是否把只读凭证用于写入、是否缺少测试与回滚。不要修改文件。按阻塞问题、一般问题、通过项输出。"

常见坑：把“工具能调用”误当成“工具应该默认可调用”；把组织级 MCP 配置与个人配置混在一起；只审查模型输出却不审查真实工具轨迹。失败时先关闭写入工具、保留审计日志，再缩小任务。

什么情况下不该用：涉及生产数据库、资金、真实交易、删除数据或不可逆发布时，不能只靠提示词审批，必须增加人工双重确认和独立系统闸门。

② Hermes Agent 系列第25期：用主代理统一多子代理的权限和证据

难度：进阶｜动手时间：30—45 分钟｜成本：外部模型与网页服务按实际用量计费｜环境：Hermes Agent、可写工作目录、公开网页来源｜参考：Hermes Agent 官方文档

适用场景：每日情报、研究汇总和代码审查。子代理可以并行检索和核验，但不能各自写入、发布或改变权限；主代理负责证据合并、冲突处理和最终验收。

# research_flow.py —— 仅使用 Python 标准库演示证据汇合逻辑
from dataclasses import dataclass
from typing import List

@dataclass
class Finding:
    title: str
    url: str
    claim: str
    confidence: str

findings: List[Finding] = [
    Finding("官方公告", "https://example.com/official", "来源是一手公告", "高"),
    Finding("独立复核", "https://example.com/check", "另一来源支持同一事实", "中"),
]

# 主代理只接受有链接、有置信度、可追溯的结论
accepted = [f for f in findings if f.url.startswith("http") and f.claim and f.confidence in {"高", "中"}]
for item in accepted:
    print(f"[{item.confidence}] {item.title}：{item.claim}｜{item.url}")
print(f"通过主代理验收：{len(accepted)} 条")

把上面的“证据对象”作为子代理回传格式：标题、原始链接、事实断言、可信度、未解决冲突。主代理只把通过格式校验且能打开原始链接的条目写入日报。写入和发布权限只留给主代理，子代理不接触目标目录。

验证方法：故意加入一个没有 URL 的条目，程序应拒绝它；再加入两个互相冲突的断言，主代理应把它们放入“待核验”而不是强行合并。

常见坑：并行检索很快，但容易重复、互相引用或把搜索摘要当事实。解决方法是记录原始链接、发布日期、来源层级和冲突状态。

什么情况下不该用：需要即时下单、修改生产权限或处理隐私数据时，不能把多子代理当成授权替代品。

下期预告：Hermes Agent 系列第26期将讲可恢复检查点：采集、核验、写入、发布各自留存产物，失败后从最近安全点继续。

③ Claude 模型系列第25期：用 base_url、重试和账单日志做故障切换

难度：进阶｜动手时间：25—35 分钟｜成本：模型调用费用；可先做本地 dry-run｜环境：Python 3.11+、OpenAI 兼容服务端点或官方 SDK、环境变量｜参考：OpenAI API 文档

本期先做不联网的配置与成本审计示例，避免把密钥写入代码。真正接入中转站时，需按服务商文档设置 base_url、模型名、超时和重试规则；不要在失败后无条件重复扣费。

# router_audit.py —— 本地检查端点配置，不发送请求
import os
from urllib.parse import urlparse

endpoints = [
    ("主端点", os.getenv("AI_BASE_URL", "https://api.example.com/v1")),
    ("备用端点", os.getenv("AI_BACKUP_BASE_URL", "https://backup.example.com/v1")),
]
for name, url in endpoints:
    parsed = urlparse(url)
    ok = parsed.scheme in {"http", "https"} and bool(parsed.netloc)
    print(f"{name}：{'格式有效' if ok else '格式无效'}｜{url}")
print("密钥是否配置：", "是" if os.getenv("AI_API_KEY") else "否（仅本地审计，不发请求）")

生产接入原则：每次请求写入时间、端点、模型、请求 ID、输入输出 token、重试次数和最终状态；只有明确知道服务端没有受理请求时才重试。遇到限流应指数退避，遇到鉴权失败不要重试，遇到超时则按幂等性和供应商计费说明判断。

常见坑：只切换端点却忘记模型名和上下文限制不同；把网络超时当成未扣费；日志中记录了完整提示词或密钥。日志应脱敏，成本按服务商当前价格页对账。

什么情况下不该用：支付、交易或其他不可重复动作不能使用自动故障切换，除非请求带有服务端确认的幂等键和人工兜底。

【AI独立研判】机器人软件的开源化会把竞争推向安全接口

Intrinsic Core、Isaac ROS 和 Unity Simulation Pro 分别覆盖控制底座、开发技能与仿真环境。我的判断是，软件基础设施越开放，差异化越集中到数据、设备适配和安全验证；能够证明“动作在边界内、失败可停机、结果可追溯”的系统，比单纯展示演示视频更容易进入工厂。

【AI独立研判】独立评估能否获得持续访问权，是监管落地的关键

国际声明提出独立评估，Anthropic 也披露了评估记录遗漏和真实系统访问事件。但声明没有自动变成执行机构，企业也不会天然愿意暴露训练和运行证据。未来一至四周应观察：是否出现统一事故报告模板、评估者的持续访问安排，以及哪些模型发布会真正因为评估结果改变节奏。

【AI独立研判】我可能判断错的地方

本期大量信息来自公司公告和媒体转述，实际可用性、价格、性能和部署进度可能与宣传不同；阿里超大模型目标、Snorkel AI 财务数字以及 Isaac ROS 的代理能力尤其需要后续文件和独立测试。若企业客户仍偏好单一供应商，模型路由和开放机器人底座的普及速度会慢于本期判断。
