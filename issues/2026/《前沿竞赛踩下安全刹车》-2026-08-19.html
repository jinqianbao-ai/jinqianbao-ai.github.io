8. “规则盲区”研究质疑合规检测器是否真的阅读了法规

信息分层：正式信息｜论文原文已核验

论文《合规检测器究竟读了什么？》报告：对多种守卫模型与激活探针删除、置换或替换规则文本，检测准确率几乎不变；甚至有模型能引用规则条款，却在换成相反许可条款后基本不改变判决。作者称这种现象为“规则盲区”，并指出逐步推理比快速检测器更能逃离该问题。

为什么重要： 企业不能因为检测器能“说出条款”就认定它按条款决策。合规评测需要加入反事实规则置换，验证判决是否真的受规则内容控制。

9. BATON 用子任务探索与交接记忆提升长周期机器人操作

信息分层：正式信息｜论文原文已核验

BATON（面向长周期操作的子任务探索与转移感知记忆方法）把整条任务的试错拆成短子任务探索，使理论探索成本从阶段数的乘法增长降为加法增长；它还记录前置条件、交接恢复和后续可继承状态。作者在 RoboMemArena 报告任务成功率提高 11.6%，累计成功提高 14.9%，且不更新模型参数。

为什么重要： 机器人长任务的关键瓶颈不是单个动作，而是动作之间能否安全交接。这个思路也适用于软件代理：每个子任务不仅要“完成”，还要给下一步留下可用状态。

① Claude Code 系列第 11 期：用 SubagentStart 与 SubagentStop 留下子代理审计账本

  • 难度： 进阶｜动手时间： 25—35 分钟｜成本： 配置免费，Claude Code 调用按订阅或 API 计费
  • 环境版本： Claude Code 当前官方文档；Python 3.9+；承接第 10 期 TeammateIdle 空闲门禁
  • 适用场景： 团队需要知道哪个子代理何时启动、属于什么类型、何时停止，以及结束时是否留下可追踪记录。官方 Hook（生命周期钩子）文档确认 SubagentStart 和 SubagentStop 均属于代理循环事件。

创建 .claude/hooks/audit-subagent.py：

#!/usr/bin/env python3
import json
import sys
from datetime import datetime, timezone
from pathlib import Path

payload = json.load(sys.stdin)
project = Path(payload.get("cwd", "."))
log_dir = project / "artifacts"
log_dir.mkdir(parents=True, exist_ok=True)

# 不假定未来字段永远不变：保留事件名与官方传入的可用标识。
record = {
    "time_utc": datetime.now(timezone.utc).isoformat(),
    "event": payload.get("hook_event_name", "unknown"),
    "session_id": payload.get("session_id"),
    "agent_id": payload.get("agent_id"),
    "agent_type": payload.get("agent_type"),
    "transcript_path": payload.get("transcript_path"),
}

with (log_dir / "subagent-audit.jsonl").open("a", encoding="utf-8") as f:
    f.write(json.dumps(record, ensure_ascii=False) + "\n")

raise SystemExit(0)

在 .claude/settings.json 中加入完整配置：

{
  "hooks": {
    "SubagentStart": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "python \"$CLAUDE_PROJECT_DIR/.claude/hooks/audit-subagent.py\"",
            "timeout": 20
          }
        ]
      }
    ],
    "SubagentStop": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "python \"$CLAUDE_PROJECT_DIR/.claude/hooks/audit-subagent.py\"",
            "timeout": 20
          }
        ]
      }
    ]
  }
}

可直接复制给 Claude Code 的任务提示词：

请把任务拆成“资料定位、实现、测试、独立审查”四个子任务，并按依赖顺序启动子代理。不要绕过现有 Hook。结束后检查 artifacts/subagent-audit.jsonl：每个已启动子代理都应至少有一条 SubagentStart 和一条 SubagentStop 记录；如果记录不成对，列出缺失的 agent_id、可能原因和需要人工检查的 transcript_path。不得把“子代理停止”自动解释为“任务成功”。

验证方法： 在 Claude Code 中用 /hooks 确认两个事件已注册；启动一次含子代理的任务后，artifacts/subagent-audit.jsonl 应出现逐行 JSON。常见坑： Hook 记录的是生命周期，不等于质量结论；字段可能因宿主或版本不同而为空，因此代码使用 get；Windows 原生环境使用 python，其他环境可改为 python3。什么情况下不该用： 项目包含高度敏感路径或会话信息、且审计文件没有访问控制时，不应记录完整 transcript 路径。

② Hermes Agent 系列第 11 期：用独立 worker lanes 给研究、写作、复核设并发边界

  • 难度： 进阶｜动手时间： 25—40 分钟｜成本： 配置免费，多个工作代理会增加模型调用费
  • 环境版本： Hermes Agent 当前官方文档；已启用 Kanban；承接第 10 期最大重试、超时与心跳熔断
  • 适用场景： 调研、撰写和复核由不同档案负责，避免多个代理在同一工作区抢文件或把“写作者自审”当独立复核。

按官方 Kanban 多档案模式，分别启动三个 worker；每条命令在独立终端或服务环境中执行：

hermes --profile researcher kanban worker --max-concurrent 2
hermes --profile writer kanban worker --max-concurrent 1
hermes --profile reviewer kanban worker --max-concurrent 1

创建带依赖关系的三项任务：

hermes kanban create "收集并核验一手来源" --assignee researcher --timeout-seconds 3600
hermes kanban create "依据已核验来源撰写中文报告" --assignee writer --timeout-seconds 3600
hermes kanban create "独立复核事实、链接与风险标识" --assignee reviewer --timeout-seconds 2400

给三个档案使用同一份交接规则：

③ Claude 模型系列第 11 期：把 429、529 与网络超时分开重试

  • 难度： 高级｜动手时间： 35—50 分钟｜成本： 示例代码免费，Claude API 按实际词元计费
  • 环境版本： Python 3.10+；anthropic>=0.60,<1；设置 ANTHROPIC_API_KEY
  • 适用场景： 承接第 10 期幂等账本。官方文档说明 SDK 默认会对连接错误、429 和 5xx 做两次指数退避重试，并在存在时遵循 retry-after；本期关闭 SDK 内置重试，显式区分限流、过载和网络超时，避免所有错误用同一策略。

安装依赖：

python -m pip install "anthropic>=0.60,<1"

保存为 claude_retry_policy.py：

import os
import random
import time
import anthropic

MODEL = os.getenv("CLAUDE_MODEL", "claude-sonnet-5")
MAX_ATTEMPTS = 5

client = anthropic.Anthropic(
    api_key=os.environ["ANTHROPIC_API_KEY"],
    max_retries=0,  # 关闭内置重试，避免与本例重复叠加
    timeout=60,
)


def wait_seconds(attempt: int, retry_after=None) -> float:
    if retry_after:
        try:
            return min(float(retry_after), 60.0)
        except ValueError:
            pass
    # 指数退避 + 随机抖动，减少多个客户端同时重试。
    return min(2 ** attempt + random.random(), 30.0)


def ask_claude(prompt: str) -> str:
    for attempt in range(MAX_ATTEMPTS):
        try:
            message = client.messages.create(
                model=MODEL,
                max_tokens=500,
                messages=[{"role": "user", "content": prompt}],
            )
            return "".join(b.text for b in message.content if b.type == "text")

        except anthropic.RateLimitError as exc:
            # 429：先尊重服务端 Retry-After；持续发生时应降低并发或申请更高额度。
            headers = getattr(getattr(exc, "response", None), "headers", {}) or {}
            delay = wait_seconds(attempt, headers.get("retry-after"))
            reason = "请求速率受限"

        except anthropic.InternalServerError as exc:
            # 529 overloaded_error 与其他 5xx 都是暂时性服务端问题。
            status = getattr(exc, "status_code", None)
            delay = wait_seconds(attempt)
            reason = "服务暂时过载" if status == 529 else "服务端暂时错误"

        except (anthropic.APITimeoutError, anthropic.APIConnectionError):
            # 超时可能处于未知状态；本例只做无副作用问答。
            delay = wait_seconds(attempt)
            reason = "网络超时或连接失败"

        except (anthropic.AuthenticationError, anthropic.PermissionDeniedError) as exc:
            raise RuntimeError("密钥或权限配置错误，不应自动重试") from exc

        if attempt == MAX_ATTEMPTS - 1:
            raise RuntimeError(f"连续失败：{reason}；已停止自动重试")
        print(f"第 {attempt + 1} 次失败：{reason}，{delay:.1f} 秒后重试")
        time.sleep(delay)


if __name__ == "__main__":
    print(ask_claude("用三句话解释为什么 API 重试需要随机抖动。"))

运行：

export ANTHROPIC_API_KEY="你的环境变量密钥"
python claude_retry_policy.py

成功标志： 正常时输出三句话；遇到 429、529 或网络问题时，控制台显示不同中文原因与等待时间；401/403 立即停止，不浪费调用。常见坑： 不要同时保留 SDK 默认重试和外层多次重试，否则次数会相乘；带副作用操作发生超时后，应先查询业务状态，不能直接重放；429 长期存在通常是并发或额度问题，不是多睡几秒就能解决。什么情况下不该用： 付款、发信、发布、删除等不可逆动作在没有幂等键和状态查询时，不得使用自动重试。
