今天这期关注 AI 从“能回答”进入“能操作”的企业系统：实时头像、机器人动作、数据库隔离、代理控制平面和长期算力合同同时出现。先读主线，再看分类要闻；每条内容均标注可信度。

一、今日主线：代理正在进入企业的操作层

过去一天最重要的变化不是某个单独模型刷新分数，而是代理开始被嵌入企业的真实操作链：它需要实时语音和视觉，需要访问生产数据，需要在表格和业务软件里执行，需要使用机器人运动规划，还需要可撤销的身份和审计记录。

  • 产品形态从聊天转向实时交互和动作输出。
  • 基础设施从 GPU 扩展到 CPU、数据库、内存、网络和权限。
  • 资本与收购开始围绕代理入口、控制平面和开源运动规划布局。

① Claude Code 系列第27期：可回放权限与审计

难度：进阶　动手时间：35—50 分钟　成本：Claude Code 按用量计费，Git 与测试免费　环境：Claude Code 2.1.199+、Git、Python 3.11+。

用 PreToolUse、PostToolUse 和 PostToolUseFailure 把敏感权限、测试结果、差异清单和审计记录串起来。官方文档说明 hook 可以在工具调用前后运行，并能阻断或记录工具请求。

  1. 先让代理只读取项目测试命令和权限文件，不写入。
  2. 阻止修改 .env、密钥、锁文件和生产配置。
  3. 记录工具名、目标、退出码、差异文件和请求时间。
  4. 通过人工复核后再合并，禁止把 hook 当成最终审批。
claude -p "请读取当前仓库的测试命令和权限配置，设计 Claude Code hooks：PreToolUse 阻止修改 .env、密钥、锁文件和生产配置；PostToolUse 记录工具名、目标、退出码和 git diff 文件清单。先不要写入，中文回答。"

claude -p "请审查当前 git diff，运行已有最小测试，并输出改动文件、测试结果、权限越界风险和缺失审计字段。不要提交、不要推送、不要修改文件，中文回答。"

常见坑：审计日志泄露密钥、hook 脚本可被代理修改、只记录退出码不记录目标。
什么情况下不该用：生产发布、支付、迁移和交易不能只依赖 hook。

② Hermes Agent 系列第27期：幂等收口与重复检测

难度：进阶　动手时间：30—45 分钟　成本：按模型与网页服务用量计费　环境：Hermes Agent、Python 3.11+、非生产测试目录。

Hermes 文档强调后台委派、并行子代理和任务收口。实践原则是：子代理只返回结构化结果，主代理使用幂等键去重后再写日报、索引和发布状态。

from pathlib import Path
import json

out = Path("agent_close_demo")
out.mkdir(exist_ok=True)

def save_once(task_id, payload):
    path = out / f"{task_id}.json"
    if path.exists():
        print("跳过重复写入：", path)
        return
    path.write_text(json.dumps(payload, ensure_ascii=False, indent=2), encoding="utf-8")
    print("首次写入：", path)

item = {"task_id":"source-01", "status":"verified", "url":"https://example.com/a"}
save_once(item["task_id"], item)
save_once(item["task_id"], item)

验证时应出现一次首次写入和一次跳过重复写入。生产任务还要记录来源 URL、失败原因、版本和最终收口者。

常见坑：子代理直接改主索引、任务键只用标题、发布成功后没有版本记录。
什么情况下不该用：不可逆外部动作不能因“没找到记录”就自动重试。

③ Claude 模型系列第27期：路由、限流预算与失败分类

难度：进阶　动手时间：35—50 分钟　成本：Claude API 按实际价格计费，本地脚本免费　环境：Python 3.11+；密钥只能通过环境变量配置。

把限流、服务端错误、超时、认证失败和参数错误分开处理；429、500、502、503、529 与超时只做有限退避，401/403 和参数错误不盲目重试。

import os

API_KEY = os.getenv("ANTHROPIC_API_KEY", "")
RETRYABLE = {"429", "500", "502", "503", "529", "timeout"}

def classify(error, attempt):
    if error not in RETRYABLE:
        print("不可重试：", error)
        return False
    delay = min(30, 2 ** attempt)
    print("可重试：", error, "；下次等待秒数：", delay)
    return True

for error in ["429", "timeout", "401"]:
    classify(error, 1)

生产接入时记录请求 ID、模型、输入/缓存/输出 token、状态码和最终成本；并发任务必须共享全局限流预算。

常见坑：所有错误都重试、备用模型能力不匹配、重试没有幂等键。
什么情况下不该用：医疗、金融、法律和高风险权限场景，备用模型只能生成待审草稿。
