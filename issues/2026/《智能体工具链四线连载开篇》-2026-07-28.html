卷首语

本期起改版：不再堆碎片快讯，一天只讲一条主线，把版面让给成体系的连载教程。教程固定四条线——Claude Code、Hermes Agent、Claude 模型接入、OpenClaw——每条线按期推进，前后衔接，不再是零散技巧。本期所有命令均在编辑本机实跑核验，版本为 Claude Code 2.1.220、codex-cli 0.145.0。

一、本期主线

正式信息｜已确认四条工具链开始分岔，选型窗口打开

把本周散落的消息合起来看，真正的变化不是某个模型涨了几分，而是智能体工具链从"一个聊天框"分化成了四种形态：Claude Code 走终端内编码代理，Hermes Agent 走常驻调度与多渠道投递，模型层被中转站抽象成可替换的后端，OpenClaw 这类早期项目则进入迁移收敛期。四者职责不同、可以叠用，这正是本期开连载的原因——单篇技巧解决不了选型问题，需要成体系地讲。

可核验的证据是命令面本身已经稳定下来：Claude Code 提供 agents、mcp、plugin、ultrareview 等子命令；Hermes 提供 skills、cron、tools、gateway、claw；而 hermes claw 只有 migrate 和 cleanup 两个动作，明确定位为"从 OpenClaw 搬家"，而非并行运行。工具链的边界已经写进 CLI 了。

正式信息｜已确认开放阵营集结，三大闭源实验室缺席

英伟达牵头成立开放安全 AI 联盟（Open Secure AI Alliance），35 家以上参与，包含微软、IBM、思科、CrowdStrike、Cloudflare、Palo Alto、Hugging Face、红帽、Databricks、Salesforce、SAP、西门子、Palantir、Linux 基金会，以及 Nous Research、Thinking Machines Lab、Reflection AI。OpenAI、Google、Anthropic 均未参与。联盟开源了智能体安全框架 NOOA，并将 Safetensors 捐给 PyTorch 基金会。

与主线的关系：模型权重与安全框架越开放，上层工具链的可替换性越强，这是第③条连载（中转与模型替换）成立的前提。

二、系列连载教程本期约占半版

四条线各出第 1 期，每期都标注难度、动手时间、成本，并说明下期接什么。所有代码可直接复制运行，密钥一律用环境变量占位。

① Claude Code 系列 · 第 1 期：从交互式聊天转向可编排的命令行代理

难度：入门到进阶｜动手时间：约 25 分钟｜成本：按所用模型 token 计费，无额外费用｜环境：Claude Code 2.1.220（本机实测）

这一期只解决一件事：让 Claude Code 从"人坐在前面聊"变成"能被脚本调用的部件"。这是后续所有自动化的地基。

1.1 非交互管道：-p 与 --bare

-p/--print 让它读完提示词就输出结果并退出，可以直接进管道。--bare 是最小模式，跳过 hooks、LSP、插件同步、CLAUDE.md 自动发现，认证严格走 ANTHROPIC_API_KEY，适合放进定时任务里求稳定。

claude -p "只回复四个字：管道可用" --bare

本机实跑输出：

管道可用 EXIT=0

能拿到干净的单行输出和 0 退出码，就说明它已经可以当 Unix 工具用了，比如把审查结果写进文件：

claude -p "用中文总结这个仓库最近的改动风险，不超过 5 条" \
  --bare > review.txt; echo "exit=$?"

1.2 权限白名单：别让代理拿到不该有的手

结合本期第三条新闻，默认就该收紧权限。--allowedTools 接受工具名并支持命令模式限定，只放行读类操作：

claude -p "分析当前分支的提交历史，指出风险点" \
  --allowedTools "Bash(git log *)" "Bash(git diff *)" "Read"

--add-dir 用来显式追加可访问目录，不写就只有当前目录。

请注意：--allow-dangerously-skip-permissions 会开启绕过全部权限检查的能力，官方帮助文本明确写着"仅推荐在无网络的沙箱中使用"。生产目录和有凭据的机器上不要用它。

1.3 自定义子代理与后台代理

--agents 直接用 JSON 定义一个专职角色，不必先建配置文件：

claude -p "审查 src 下的改动" --agents '{
  "reviewer": {
    "description": "Reviews code",
    "prompt": "你是严格的中文代码审查员，只报可复现的问题"
  }
}' --agent reviewer

长任务用 --bg/--background 丢到后台，立即返回，之后用 claude agents 管理。

下期预告（第 2 期）：把 claude mcp 接上外部数据源，并用 claude ultrareview 做分支级多代理审查。

② Hermes Agent 系列 · 第 1 期：把能力装上，把手脚管住

难度：入门｜动手时间：约 20 分钟｜成本：无（本地 CLI 操作）｜环境：本机 Hermes，Windows + Git-Bash

Hermes 与 Claude Code 的分工是：前者常驻、管调度与投递，后者专精编码。这一期讲清能力怎么装、权限怎么收、任务怎么定时。

2.1 技能安装与工具开关

技能是可复用的操作手册，装好之后 Agent 会自己按需加载。检索与安装：

hermes skills search "github"
hermes skills inspect <技能名>   # 先预览，不落盘
hermes skills install <技能名>
hermes skills list

装之前先 inspect，这是个好习惯——技能里可能带命令，看一眼再决定。工具面用 tools 收放，内置工具集用普通名字，MCP 工具用 服务器:工具 记法：

hermes tools list
hermes tools disable web
hermes tools enable web

2.2 定时任务：让它按点干活

hermes cron list
hermes cron create        # 交互式创建
hermes cron run <任务ID>   # 立刻试跑一次，别等到点
hermes cron pause <任务ID>

新建定时任务后，务必先 run 一次验证，否则错误会等到计划时间才暴露。任务提示词要写成自包含的，因为它在全新会话里执行，没有当前聊天的上下文。

本报实操记录：本期改版本身就是这么落地的——把版式规则写进定时任务的提示词，再核对存档确认生效，而不是每天靠人工叮嘱。

下期预告（第 2 期）：用 hermes gateway 打通消息渠道，并用 hermes doctor 排查投递失败。

③ Claude 模型系列 · 第 1 期：中转接入与成本对账

难度：入门｜动手时间：约 15 分钟｜成本：取决于中转站计费｜要点：密钥只走环境变量

3.1 用中转站作为模型后端

多数工具（含 Claude Code）都认 ANTHROPIC_BASE_URL 与 ANTHROPIC_API_KEY 这组环境变量，把 base url 指向中转站即可替换后端，无需改代码：

export ANTHROPIC_BASE_URL="https://api.jinqianbao.icu/"
export ANTHROPIC_API_KEY="$MY_RELAY_KEY"   # 从密钥管理器读，别写进脚本
claude -p "只回复两个字：连通" --bare

Hermes 侧则用 hermes model 选择默认模型与供应商，自定义供应商以 custom:<名称> 形式引用；失败切换用 hermes fallback 配置。

未核验，请以官方文档与中转站控制台为准：各中转站支持的模型别名、限流策略与计费单价各不相同，本文不列具体价格。密钥务必用环境变量或 hermes secrets 托管，不要提交进仓库。

3.2 成本对账：先算再换

换后端前用一段纯标准库脚本估算量级，避免凭感觉决策。下面这段在编辑本机实跑通过：

from dataclasses import dataclass

@dataclass
class Plan:
    name: str
    in_price: float    # 每百万输入 token 单价（美元，占位示例）
    out_price: float   # 每百万输出 token 单价

def monthly(p: Plan, calls: int, tin: int, tout: int) -> float:
    return (calls * tin * p.in_price + calls * tout * p.out_price) / 1_000_000

if __name__ == "__main__":
    # 场景：每天 200 次长文摘要，输入 8000、输出 600 token
    calls, tin, tout = 200 * 30, 8000, 600
    for p in (Plan("方案A", 0.25, 1.25), Plan("方案B", 5.00, 25.00)):
        print(f"{p.name}: 月费约 {monthly(p, calls, tin, tout):.2f} 美元")

本机实跑输出：

方案A: 月费约 13.68 美元 方案B: 月费约 288.00 美元

两者相差 21 倍。表内单价为占位示例，不是任何厂商真实报价，请替换为你自己账单上的数字再看结论。

④ OpenClaw 系列 · 第 1 期：把资产迁出来，别两套并行

难度：入门｜动手时间：约 10 分钟｜成本：无｜前置：先备份原目录

4.1 迁移设置、记忆、技能与密钥

先把事实说清楚：本机 hermes claw --help 显示它只有两个子命令，官方描述是"从 OpenClaw 迁移设置、记忆、技能和 API 密钥到 Hermes"。也就是说这条线的定位是收敛迁移，而不是长期并行运行两套代理。

hermes claw --help          # 确认可用动作
hermes claw migrate         # 迁移设置/记忆/技能/密钥
hermes claw cleanup         # 迁移完成后归档遗留目录

迁移后建议按顺序自查：

hermes skills list          # 技能是否都在
hermes memory               # 记忆是否带过来
hermes doctor               # 整体健康检查
顺序很重要：cleanup 会归档遗留目录，必须等 migrate 结果验证无误后再执行。动手前先手工备份一份 OpenClaw 配置目录，迁移工具不保证覆盖所有自定义文件。

下期预告（第 2 期）：迁移后的技能冲突排查与 hermes skills diff 比对本地改动。

三、独立研判（非新闻事实）

以下是本报观点，不是已发生的事实，请与上文分层信息区分开。

工具链的竞争重心正在从模型能力转向权限模型。本期三条消息放在一起看，指向同一件事：能力已经够用，敢不敢放手才是瓶颈。越界事件之后，"默认最小权限 + 显式白名单"会比"更强的模型"更快成为选型硬指标。--allowedTools 这类开关的存在感会越来越强。

中转层会长期存在，但要做好被抽象掉的准备。Safetensors 进入 PyTorch 基金会、安全框架开源，都在削弱单一供应商的锁定力。中转站的价值将从"能用上"转向"稳定性与对账透明度"。

对个人使用者，最优解是分工而非二选一。Claude Code 管编码闭环，Hermes 管常驻调度与投递，模型层保持可替换，OpenClaw 这类早期项目及时迁移收敛。这也是本报把连载分成四条线的判断依据。
