重点一：Meta 推出可本地运行的 Muse Glimmer 30B 多模态开放模型

正式信息｜已确认

Hugging Face 8 月 10 日发布首日适配说明：Meta 的 Muse Glimmer 是一个 300 亿参数的稠密多模态模型，由约 20 亿参数视觉编码器和 280 亿参数文本解码器组成，采用 Apache 2.0 许可，面向本地智能体、编程、文档分析、个人助手和隐私敏感场景。模型首日获得 Transformers、llama.cpp、vLLM 与推理端点支持；官方示例显示它可处理文本、图片和无音频视频，并可选用推测解码模块加速结构化生成。

为什么重要： “开放权重”开始从下载文件升级为一整套可运行交付：明确许可、主流推理框架首日支持、消费级或单机部署目标、多模态输入和智能体工具使用。模型能否快速进入现有工程栈，正变得与榜单分数同样重要。

9. 论文显示：一张纸上的文字就可能劫持视觉语言模型控制的机器人

正式信息｜已确认

arXiv:2608.05715 对视觉语言模型控制的机器人进行了 5,670 次物理提示注入试验，攻击文字被直接放进机器人视野。作者报告 GPT-4o、Gemini 2.5 Flash、Qwen3-VL-32B 的攻击成功率分别为 27.0%、29.4% 和 5.0%；提示防御、两阶段复核和文字遮罩在其基准中可显著降低风险，文字遮罩达到 100%，但可能伤害必须读取现场标签的任务。

10. “AI 科学家”综述指出：代码能运行，不等于研究结论可核验

正式信息｜已确认

① Claude Code 系列第 5 期：让“测试”和“安全审查”各司其职

  • 难度： 进阶
  • 预计动手时间： 25—35 分钟
  • 成本： 配置免费；调用子代理按所选 Claude 模型计费
  • 环境版本： Claude Code v2.1.205+；项目已有可运行测试
  • 适用场景： 上一期已经用 PostToolUse 自动跑最小测试，希望再增加只读安全审查，但不让审查代理直接改代码。

把确定性测试留给 Hook，把开放式判断交给只读子代理。项目内创建 .claude/agents/security-reviewer.md：

---
name: security-reviewer
description: 修改完成且测试通过后，主动审查安全、权限边界和输入验证
tools: Read, Glob, Grep
model: sonnet
permissionMode: plan
maxTurns: 8
---

你是只读安全审查员。只检查本次改动及其直接调用链，不修改文件。
必须依次检查：
1. 外部输入是否在进入 shell、SQL、模板、文件路径前被约束；
2. 密钥、令牌、个人信息是否可能写入日志或错误信息；
3. 新增工具调用是否扩大权限、网络访问或持久化范围；
4. 失败分支是否会绕过鉴权、重试边界或幂等控制；
5. 测试是否覆盖至少一个拒绝路径。

输出固定为：严重问题、一般问题、缺失测试、可以合并的理由。
没有发现问题时也要明确写“未发现阻断合并的问题”，并列出仍未覆盖的风险。

然后在 Claude Code 中直接发出完整任务：

请先完成当前功能修改并运行项目现有测试。测试通过后，调用 security-reviewer 子代理做只读审查。主线程不得根据猜测宣称安全；必须把子代理发现的问题逐条列出。若存在严重问题，先停止合并并给出最小修复方案；若无严重问题，再给出测试结果和合并建议。

验证方法： 子代理只应拥有 Read、Glob、Grep；输出中应出现四个固定栏目，且不会调用 Write 或 Edit。Claude Code 官方说明，项目子代理位于 .claude/agents/，YAML 中 tools 是允许工具清单，permissionMode: plan 为只读规划模式，maxTurns 可限制代理回合数。

常见坑： 首次在会话中创建 .claude/agents/ 目录后，官方文档提示可能需要重启一次会话；不要给安全审查员 Bash、Write、Edit，否则“审查”可能变成未经批准的修复；模型名应使用账户可用别名或完整模型 ID。

什么情况下不该用： 涉及正式渗透测试、合规认证或高危生产变更时，子代理审查不能替代专业安全人员和独立测试环境。

https://code.claude.com/docs/en/sub-agents

  • 成本： 技能文件免费；定时运行按固定模型计费
  • 环境版本： 以 Hermes Agent 当前官方 Skills 与 Cron 文档为准
  • 适用场景： 已经有三个可用技能，希望无人值守任务按固定顺序执行，并在密钥、技能依赖或投递配置缺失时不烧词元。

Hermes 的 Cron 可以在任务开始前加载一个或多个技能，并按声明顺序叠加；调度器还会在构造智能体前检查服务商密钥、技能依赖和投递目标。下面用自然语言创建，避免依赖不同版本可能变化的长参数组合：

请创建一个名为“每日项目情报链”的定时任务，每天北京时间 09:00 运行，工作目录固定为 C:/work/my-project，固定使用我已经配置并核验的低成本模型和服务商。

运行前依次加载以下三个已安装技能：
1. collect-changes：采集过去24小时提交、发行版和持续集成变化；
2. verify-sources：打开原始链接，区分官方信息、媒体报道和未经证实内容；
3. archive-report：把最终中文报告写入工作目录下 reports/当天日期.md。

任务要求：
- 任一步失败都停止后续步骤，并用中文说明失败位置；
- 没有变化时只输出 [SILENT]；
- 不创建新的定时任务，不修改三个技能；
- 先执行 Cron 预检，密钥、技能依赖或投递配置缺失时不得调用模型；
- 创建后立即显示任务摘要，但不要立刻触发正式运行。

技能说明文件需要明确声明依赖。一个最小 ~/.hermes/skills/verify-sources/SKILL.md 可写为：

---
name: verify-sources
description: 打开原始来源，核验日期、事实与可信度分层
---

# 来源核验

1. 优先打开公司、监管机构、论文或代码仓库原页。
2. 搜索摘要只能用于发现线索，不能作为最终证据。
3. 每条输出：中文标题、事实摘要、来源、原始链接、发布时间、可信度。
4. 无法打开原页时降级为“媒体报道｜待官方完整确认”。
5. 匿名爆料必须写“行业风声｜未经证实”，并说明证据弱点。

验证方法： 创建后查看任务摘要，确认工作目录、模型固定项和三个技能顺序正确。首次试运行应观察三种结果之一：成功完成、业务失败、blocked_config；官方文档说明预检失败时只报警一次且不会发起模型调用。

常见坑： 技能名称必须与已安装技能一致；Cron 在全新会话运行，任务提示必须写全 URL、目录和输出要求；有工作目录的任务会按调度 tick 串行执行；定时任务内不能递归创建新 Cron。

什么情况下不该用： 需要强事务、秒级触发或必须保证外部写入恰好一次时，不应只依赖普通 Cron，应在业务系统增加队列与幂等键。

③ Claude 模型系列第 5 期：按任务、模型与线路做每日成本对账

  • 难度： 进阶
  • 预计动手时间： 20—30 分钟
  • 成本： 对账脚本免费；模型请求按真实用量计费
  • 环境版本： Python 3.10+，延续上期生成的 claude_usage.jsonl
  • 适用场景： 已经记录每次调用的输入、缓存与输出词元，希望按任务和中转线路汇总，并在月度预算接近上限时报警。

将上期账本每行补充 task、provider 和各项单价；价格必须来自你的实际合同或官方价格页。保存为 claude_cost_report.py：

import json
import os
from collections import defaultdict
from datetime import datetime
from pathlib import Path

LEDGER = Path(os.getenv("CLAUDE_LEDGER", "claude_usage.jsonl"))
MONTH = os.getenv("REPORT_MONTH", datetime.now().strftime("%Y-%m"))
BUDGET_USD = float(os.getenv("MONTHLY_BUDGET_USD", "100"))

# 单位均为“美元/百万词元”。请按你的真实线路填写，不要照抄示例。
PRICES = {
    "official/claude-sonnet-5": {
        "input": 2.00,
        "cache_read": 0.20,
        "cache_write": 2.50,
        "output": 10.00,
    },
    "relay/claude-sonnet-5": {
        "input": 2.20,
        "cache_read": 0.22,
        "cache_write": 2.75,
        "output": 11.00,
    },
}

def usd(tokens, price):
    return float(tokens or 0) / 1_000_000 * price

rows = defaultdict(lambda: {"calls": 0, "usd": 0.0})
with LEDGER.open(encoding="utf-8") as f:
    for line in f:
        item = json.loads(line)
        if not str(item.get("time", "")).startswith(MONTH):
            continue
        route = f"{item.get('provider', 'unknown')}/{item['model']}"
        if route not in PRICES:
            raise SystemExit(f"缺少价格配置：{route}")
        p = PRICES[route]
        cost = (
            usd(item.get("input_tokens"), p["input"])
            + usd(item.get("cache_read_input_tokens"), p["cache_read"])
            + usd(item.get("cache_creation_input_tokens"), p["cache_write"])
            + usd(item.get("output_tokens"), p["output"])
        )
        key = (item.get("task", "未分类"), route)
        rows[key]["calls"] += 1
        rows[key]["usd"] += cost

total = sum(v["usd"] for v in rows.values())
print(f"月份：{MONTH}  总成本：${total:.2f}  预算：${BUDGET_USD:.2f}")
for (task, route), value in sorted(rows.items(), key=lambda x: -x[1]["usd"]):
    print(f"{task:16} {route:32} {value['calls']:4d} 次  ${value['usd']:.2f}")

ratio = total / BUDGET_USD if BUDGET_USD else 1
if ratio >= 1:
    raise SystemExit("预算已超限：请暂停非必要任务或切换低成本模型。")
elif ratio >= 0.8:
    print("警告：本月预算已使用 80% 以上。")

运行：

export CLAUDE_LEDGER="claude_usage.jsonl"
export REPORT_MONTH="2026-08"
export MONTHLY_BUDGET_USD="100"
python claude_cost_report.py

验证方法： 先用一行示例账本运行，应看到月份、总成本、任务、线路和调用次数。把预算临时改成 0.01，应触发中文超限退出。Anthropic 当前定价页显示 Claude Sonnet 5 在 2026 年 8 月 31 日前采用介绍价，9 月 1 日起价格变化，因此价格表必须按月份维护。

常见坑： 中转线路可能把缓存词元合并进普通输入，需按它真实返回字段调整；新分词器可能让同一文本产生更多词元，不能用字符数反推费用；示例中的中转加价只是演示，不代表任何服务商报价。

什么情况下不该用： 需要财务审计、发票对账或税务入账时，本地估算不能替代服务商账单、合同和发票。
