今日主线：从模型参数到每瓦有效工作

OpenAI在8月25日连续发布自研推理芯片 Jalapeño 的首批测量结果，并解释其“全栈”策略：模型、服务软件、芯片、内存、网络、数据中心和产品共同优化。官方称，在其引用的 InferenceX 测试中，Jalapeño在多个公开模型上同时取得更高吞吐/瓦和更低延迟；这些数字仍属于厂商披露。

自研推理芯片进入实测阶段

正式信息｜已确认 OpenAI称Jalapeño是首款自研推理芯片，在 GPT‑OSS 120B、DeepSeek R1、Kimi K2.5 1T上测试。官方披露峰值吞吐下每瓦有效工作约为对比系统的1.5—1.9倍，端到端延迟降低约1.7—3.6倍；互动负载性能最高约提升2.1—4.1倍。可信度高，但性能数字仍待独立复测。

与主线关系：长链智能体会放大单步延迟与重试成本，硬件效率可能直接影响可用步骤数和服务价格。

开放模型把训练方法与部署接口一起交付

正式信息｜已确认 IBM Granite 4.2发布3B、8B、30B规模，支持思考切换、低努力思考、原生工具调用和最长512K上下文；8B与30B经过真实沙盒中的智能体强化学习。文章称可通过兼容 OpenAI 格式的服务接入 vLLM 与 SGLang，并以 Apache 2.0许可证发布。

与主线关系：开放模型的竞争重点扩展到能否以合理成本接入真实工作流。

企业代理开始触碰权限、成员与预算

正式信息｜已确认 OpenAI推出 ChatGPT Work 和 Codex 的 Admin plugin（管理员插件），支持分析使用量、管理成员与群组、检查权限、调整限额和处理支出申请。官方强调沿用既有角色和权限，不自动扩大访问范围。

与主线关系：模型能执行管理动作后，成本控制和权限边界就成为产品核心性能。

① Claude Code系列｜第16期：给MCP工具加输入输出契约测试

难度：进阶　动手：25分钟　成本：免费　环境：Python 3.11+，已配置可调用的MCP工具。适合在真实执行前拦截错字段、缺字段和未知字段。

  1. 新建 test_tool_contract.py，复制以下完整代码。
  2. 把 weather_lookup和字段规则换成自己的工具，先不连接生产系统。
  3. 运行 python test_tool_contract.py，看到最后一行“全部契约测试通过”才进入下一步。
import json
TOOL_SCHEMA = {"name":"weather_lookup","required":{"city":str,"days":int},"optional":{"unit":str}}
CASES = [{"city":"上海","days":3,"unit":"摄氏度"},{"city":"北京","days":1}]
def validate(payload):
    assert isinstance(payload, dict), "输入必须是对象"
    for key, typ in TOOL_SCHEMA["required"].items():
        assert key in payload, f"缺少必填字段：{key}"
        assert isinstance(payload[key], typ) and not isinstance(payload[key], bool), f"字段类型错误：{key}"
    allowed=set(TOOL_SCHEMA["required"])|set(TOOL_SCHEMA["optional"])
    assert not (set(payload)-allowed), f"出现未声明字段：{sorted(set(payload)-allowed)}"
    return {"ok":True,"tool":TOOL_SCHEMA["name"],"arguments":payload}
for i,case in enumerate(CASES,1): print(f"用例{i}通过：{json.dumps(validate(case),ensure_ascii=False)}")
print("全部契约测试通过")

常见坑：只测字段存在、不测类型；测试工具和生产工具共用有副作用后端；只测成功样例。失败时先保存 JSON，再单独运行校验器。生产写操作必须另加隔离环境和人工确认。

参考：MCP规范、Claude Code文档。下期预告：第17期建立只读/写入分级权限与人工确认门。

② Hermes Agent系列｜第16期：多子代理结果合并与冲突门控

难度：进阶　动手：20分钟　成本：免费　环境：Python 3.11+，能输出JSON的子代理编排环境。不要用“多数表决”替代证据核验。

import json
reports=[
 {"agent":"官方来源代理","claim":"Jalapeño为自研推理芯片","source":"https://openai.com/index/jalapeno-first-results","confidence":0.95},
 {"agent":"复核代理","claim":"Jalapeño为自研推理芯片","source":"https://openai.com/index/the-full-stack-behind-abundant-intelligence","confidence":0.90},
 {"agent":"社区代理","claim":"性能已被独立复测","source":"","confidence":0.35}]
def merge(items):
 groups={}
 for item in items: groups.setdefault(item["claim"],[]).append(item)
 out=[]
 for claim,items in groups.items():
  sources=[x["source"] for x in items if x.get("source")]; score=max(x.get("confidence",0) for x in items)
  out.append({"claim":claim,"status":"可进入摘要" if sources and score>=0.8 else "需要人工复核","evidence_count":len(sources),"agents":[x["agent"] for x in items]})
 return out
print(json.dumps(merge(reports),ensure_ascii=False,indent=2))

预期：芯片结论可进入摘要，独立复测结论需要人工复核。常见坑是重复计数同一来源、把代理数量当证据强度。涉及转账、删除、权限和部署时必须人工批准。参考：Hermes Agent文档。下期预告：第17期让失败重跑只重跑证据不足的子任务。

③ Claude模型系列｜第16期：上下文压缩前后的成本与可追踪性

难度：入门到进阶　动手：20分钟　成本：免费离线账本，模型调用费用另计　环境：Python 3.11+，JSONL请求账本。

import json
from pathlib import Path
path=Path("claude_usage.jsonl")
if not path.exists(): path.write_text('{"task":"需求分析","before_input_tokens":12000,"after_input_tokens":4200,"output_tokens":900,"cost_usd":0.18}\n{"task":"代码审查","before_input_tokens":18000,"after_input_tokens":7000,"output_tokens":1400,"cost_usd":0.31}\n',encoding="utf-8")
rows=[json.loads(x) for x in path.read_text(encoding="utf-8").splitlines() if x.strip()]
for r in rows:
 saved=r["before_input_tokens"]-r["after_input_tokens"]; ratio=saved/r["before_input_tokens"] if r["before_input_tokens"] else 0
 print(f"{r['task']}：输入词元减少 {saved}，压缩率 {ratio:.1%}，费用 ${r['cost_usd']:.2f}")
print(f"共记录 {len(rows)} 次；压缩前 {sum(r['before_input_tokens'] for r in rows)}；压缩后 {sum(r['after_input_tokens'] for r in rows)}")

建议保留目标、约束、确认事实、未解决问题和最近失败原因；删除重复礼貌语和可重新读取的长原文。常见坑：只看输入词元、不看重试；压缩掉权限约束；混用不同模型线路。法务、医学、财务原文不应只靠自动摘要替代。参考：Anthropic词元计数文档。下期预告：第17期讨论压缩摘要回滚与原文指针。
