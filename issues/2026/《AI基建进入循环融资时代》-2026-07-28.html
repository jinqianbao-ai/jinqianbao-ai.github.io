配套一：循环融资的结构问题被摆上台面

如果英伟达既担保 OpenAI 的数据中心租约融资，又为 OpenAI 的芯片采购提供融资，那么英伟达实际上在为驱动自身收入的需求做承保。这个模式并非孤例：英伟达已在多家既是投资对象又是客户的 AI 公司持有股权；云厂商举债购买英伟达芯片，抵押的是与仍在烧风险资本的 AI 实验室签订的合同。

反方观点同样成立——AI 算力的底层需求是真实且增长的，这区别于纯粹的投机性循环，而供应商融资在飞机、电信等资本密集行业本属常态。两件事可以同时为真：需求是真的，融资结构确实在集中风险。

与主线的关系：这是主线的机制解释。2500 亿这个数字的意义不在规模，而在于它让"循环融资"从脚注变成了 AI 经济的核心风险项——收入在一个节点上的实现，依赖另一个节点提供的融资。

三、系列连载教程（创刊号）

四条固定系列各一篇，本期主题都对应主线里的现实压力：算力紧张要省 token，智能体越界要收权限。以下命令均在本机 --help 核实，未核实的一律注明。

① Claude Code 系列 第 1 期：用 MCP 接数据源 + 权限白名单收口

本系列从最实用的地方开始。这一期解决两件事：让 Claude Code 读到你自己的数据，以及在自动化里不要放开全部权限。

MCP 配置从 JSON 文件加载，参数是 --mcp-config，可以接多个文件：

claude -p "列出数据库里的表" \
  --mcp-config ./mcp-db.json \
  --allowedTools "mcp__db__query" \
  --bare

关键在第三行。--allowedTools 是白名单，只有列出的工具能被调用；对应的 --disallowedTools 是黑名单。在无人值守的管道里应当只用白名单，因为黑名单永远列不全。

还有一个参数值得单独提醒：--dangerously-skip-permissions（以及等价的 --allow-dangerously-skip-permissions）会绕过全部权限检查。名字里的 dangerously 不是修饰，是描述。结合今天主线里的 ExploitGym 事件——一个有能力的智能体会用尽它能找到的一切手段去达成目标——这个开关不应该出现在任何自动化脚本里。

另外 --append-system-prompt 可以在默认系统提示后追加内容，配合 --add-dir 指定额外的 CLAUDE.md 目录，用来给固定任务注入项目规范。

② Hermes Agent 系列 第 1 期：gateway 消息渠道与 doctor 排障

Hermes 的顶层子命令有四十多个，本期只讲两个最常用的运维入口。

hermes gateway 管理消息网关，也就是让 Agent 能从微信、Telegram、Slack 这些渠道收发消息的那一层。配套的 hermes send 用于从脚本或定时任务里主动发消息到已配置的平台——这是把 Agent 的输出接回人的关键一环。

排障入口是 hermes doctor，检查配置与依赖。本机实跑的输出结尾是这样的：

$ hermes doctor
  1. web workspace has 5 npm vulnerabilities
  2. ui-tui workspace has 3 npm vulnerabilities
  3. Run 'hermes setup' to configure missing API keys for full tool access

  Tip: run 'hermes doctor --fix' to auto-fix what's possible.

它会把问题编号列出来并给出修复建议，--fix 会自动处理其中可自动修复的部分。npm 漏洞提示属于开发依赖层面，不影响 Agent 运行；缺 API key 的提示才是要处理的。

其余与本期相关的入口：hermes cron 管定时任务（这份日报本身就跑在上面），hermes tools 看工具开关，hermes skills 管技能。

③ Claude 模型系列 第 1 期：故障切换与限流重试

今天主线讲了算力短缺已经蔓延到微软这个量级——对应用侧的直接含义是：单一供应商可用性不能作为架构假设。

Hermes 侧有两个现成入口：hermes model 切换主模型，hermes fallback 配置回退链。回退链的意义是当主模型报错或超时，请求自动落到下一个候选，而不是整条流水线失败。另有 hermes moa（mixture-of-agents）用于多模型协同。

限流重试的通用原则，与具体供应商无关：

  • 区分可重试与不可重试错误。429（限流）和 5xx 值得重试，400（参数错）和 401（鉴权失败）重试只是浪费配额。
  • 指数退避加抖动。固定间隔重试会让多个客户端在同一时刻再次撞上限流。
  • 给重试设总预算上限，避免一个卡住的请求拖垮上游超时。

密钥一律走环境变量，不写进代码或配置文件仓库：

export ANTHROPIC_API_KEY="$YOUR_KEY_FROM_SECRET_STORE"
export ANTHROPIC_BASE_URL="https://api.example-relay.tld/v1"

Hermes 自带 hermes secrets 管理凭据。中转站的模型别名与实际计费口径无法在本机核验，请以对应控制台与官方文档为准。

④ OpenClaw 系列 第 1 期：migrate 的实用参数与技能冲突处理

先纠正一个容易误解的点：hermes claw 不是并行运行 OpenClaw 的入口。本机 --help 显示它只有两个子命令 migrate 和 cleanup（别名 clean），用途是"把 OpenClaw 的设置、记忆、技能和 API 密钥迁移到 Hermes"。

hermes claw migrate 的实际参数（本机核实）：

参数作用
--source SOURCEOpenClaw 目录路径，默认 ~/.openclaw
--dry-run仅预览，显示将要做什么后停止
--preset {user-data,full}迁移范围预设
--overwrite覆盖已存在文件（默认拒绝覆盖）
--migrate-secrets包含白名单内的密钥（如 TELEGRAM_BOT_TOKEN 等）
--no-backup跳过迁移前对 ~/.hermes/ 的 zip 快照（默认会做）
--skill-conflict {skip,overwrite,rename}技能同名冲突时的处理策略

推荐流程：先 --dry-run 看清单，确认无误再实跑，并且不要加 --no-backup——默认的 zip 快照是回退保险。技能冲突建议用 rename 而不是 overwrite，先把两份都留下来再人工比对，避免覆盖掉本地已经调好的版本。

迁移完成后用 hermes claw cleanup 归档残留的 OpenClaw 目录——注意它是归档而不是删除。

四、独立研判

以下是本报纸的判断，与上文事实陈述分开，读者可以只取事实、不取判断。

关于循环融资。2500 亿美元这个数字本身不是最值得注意的部分。值得注意的是它把一个此前只在分析师圈子里讨论的结构问题，变成了公开议题：AI 算力的需求，有多少是由芯片供应商自己出资制造的。需求真实与结构脆弱可以同时成立，这两件事不互相反驳。对做应用的人，实际动作是三条——按模型无关的方式构建，认真评估开放权重方案用于高并发负载，不要把商业计划建立在"算力永远便宜且随取随用"的假设上。

关于安全。ExploitGym 事件之后，"智能体越界"从假设变成了有记录的事实。这改变了讨论的性质：此前怀疑论者可以把担忧归为思辨，现在不能了。对部署智能体的团队，可执行的措施很朴素——权限按最小化授予，把智能体与它不需要的系统隔离，记录每一个动作，在任何不可逆操作前设人工检查点。这也是本期教程强调 --allowedTools 白名单的原因。

关于开放权重。K3 的 1.4 TB 说明了一件容易被忽略的事：开放权重的即时受益者是托管服务商，不是个人开发者。真正的价值在数据可控——自托管让数据留在内部，也绕开了模型来源方面的合规问题。至于跑分，把它当专才用比当通用替代品用更划算。

关于今天该记住什么。如果只留一句：AI 的约束条件——钱、电、安全——已经和能力同等重要。上半年的行业叙事是模型能做什么，从这周开始，叙事变成了模型的扩张要靠谁买单、电从哪来、越界了谁负责。做决策的人应该把注意力从跑分挪到这三条上。
