今日主线：智能体安全正在从“模型行为”下沉为“基础设施能力”

今天最值得关注的变化不是又一个模型分数，而是智能体的安全边界开始被做成可独立执行的基础设施。NVIDIA 发布 Open Agent Safety Platform，把策略、运行时和硬件监控放在模型之外；H Company 发布面向电脑操作的 Holo4，说明跨界面执行继续扩张；与此同时，OpenAI、Anthropic 和研究社区都在把事故披露、独立评测和完整轨迹纳入讨论。

  • 基础设施：安全策略不再只依赖模型自觉，而要能在运行时拒绝越权行动。
  • 产品形态：智能体正在接管图形界面、代码、MCP 和 API，授权问题随之扩大。
  • 验证方法：单轮问答分数不足以证明长期任务安全，需要看完整轨迹、跨模态输入和失败恢复。

NVIDIA 发布开放智能体安全平台，把边界控制下沉到运行时与硬件

NVIDIA 宣布 Open Agent Safety Platform，由开源 OpenShell 安全运行时和 NVIDIA Sentry 参考系统组成。OpenShell 在智能体进程之外追踪行动并执行策略，Sentry 则通过 BlueField-4 DPU 提供独立监控和隔离能力。官方称平台面向从测试到部署的全生命周期，并联合多家企业推进生态合作。

为什么重要：这说明智能体安全正在从提示词和模型行为层，扩展到操作系统、网络、芯片与机器人执行层。对企业而言，权限策略若只写在提示词里，无法替代运行时的强制执行。

arXiv 提出统一评测框架：模型看输出，智能体看轨迹，多模态系统看跨模态关系

论文《面向可信大语言模型、智能体与多模态系统的统一评测框架》提出共同的评测骨架，并按系统类型增加不同测量单元。普通大语言模型关注输出，智能体关注完整行动轨迹，多模态系统关注跨模态关系，同时纳入安全、可靠性和元评测。论文属于研究提案，不能直接等同于行业标准。

为什么重要：这套划分提供了一个实用的采购和验收视角：不要用聊天问答分数替代对工具调用、委派、恢复和越权的检查。它也能帮助团队把“模型变强”与“系统变可靠”拆开测量。

MME-Safety 为多模态模型安全建立细粒度基准，专门覆盖跨模态绕过风险

论文 MME-Safety 提出多模态大模型安全评测基准，使用风险场景、伤害严重程度和模态相关隐蔽性等维度进行标注。作者指出，图像、文本和其他模态的组合可能绕过单模态过滤器。论文最新版本于 9 月 22 日修订，仍应等待更多独立复现。

为什么重要：多模态安全不能只把文本安全测试搬到图像问答上。对视频、截图、语音和图文混合输入，企业需要额外验证模型是否能理解真正意图、拒绝危险组合并保持一致行为。

把非交互执行、权限模式和 JSON 输出组成可审计流水线

参考：官方文档

# 先只读规划：不修改文件，也不接受权限提示
claude -p --permission-mode plan --permission-prompts none --output-format json "请阅读当前仓库，输出：1. 目标；2. 相关文件；3. 风险；4. 测试计划。不要修改文件。"

# 再执行实现：仍然要求输出机器可解析结果
claude -p --output-format json "根据上一阶段的计划实现最小改动。先补充测试，再运行测试；最后输出修改文件、测试命令、测试结果和未解决风险。"

# 需要 MCP 时显式限定配置来源
claude -p --strict-mcp-config --mcp-config ./mcp.json --output-format json "只使用 mcp.json 中的只读工具，检查接口文档与当前实现，不要写入外部系统。"

成功标准是第二阶段输出中同时出现修改文件、测试命令和测试结果，并且人工检查 git diff。常见坑是把 `--permission-prompts none` 误当成安全沙箱；它只是无人值守时拒绝需要询问的操作。不要在生产数据库、真实交易账户或不可逆迁移上直接使用无人值守执行。

Hermes Agent 系列第29期｜进阶｜动手时间：25—40 分钟｜成本：需要 Hermes Agent、可用模型提供商和一个仅允许写入目标目录的任务环境；Cron 本身不额外收费，但模型和网络调用按实际用量计算。

用 Cron 的新会话、技能注入和失败状态做可恢复日报任务

参考：官方文档

# 面向读者的配置示例：把采集、核验和写入约束写进任务提示
hermes cron create "0 9 * * *" "检索最近24小时人工智能行业信息；优先官方来源；至少核验8条；写入指定日报目录；发布前重新读取文件并检查链接。" --name "每日人工智能日报" --skill ai-daily-research

# 查看任务状态；重点区分成功、执行失败、投递失败和配置阻断
hermes cron list
hermes cron status

Cron 每次运行都使用新的 Agent 会话，技能按顺序注入；任务提示必须自包含，不能依赖上一轮对话。验收时要看任务状态和本地成品，而不是只看模型有没有返回文字。常见坑是把 `ok` 当成“用户一定收到了”：文档区分执行成功与投递失败。涉及真实外部写入时，应先做只读演练。

Claude 模型系列第29期｜进阶｜动手时间：15—25 分钟｜成本：需要 Python 3.9+、`openai` Python 包和对应服务的 API 密钥；费用按所选模型与服务商价格计算。密钥必须通过环境变量注入。

用 OpenAI SDK 兼容接口接入 Claude，并保留可切换的 base_url

参考：官方文档

# 安装官方 OpenAI SDK（示例命令，版本以官方文档为准）
pip install -U openai

# claude_compat.py
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["MODEL_API_KEY"],
    base_url=os.environ.get("MODEL_BASE_URL", "https://api.anthropic.com/v1/"),
)
response = client.chat.completions.create(
    model=os.environ["MODEL_NAME"],
    messages=[
        {"role": "system", "content": "你是一个严谨的中文助手。"},
        {"role": "user", "content": "用三句话解释什么是智能体运行时安全。"},
    ],
)
print(response.choices[0].message.content)

运行前设置 `MODEL_API_KEY`、`MODEL_BASE_URL` 和 `MODEL_NAME`。常见报错来自模型名不属于该端点、兼容层不支持某参数、限流或 base_url 多写了一层路径；遇到 429/5xx 应记录请求 ID并按官方重试建议处理。不要把不同服务商的价格、上下文长度和安全策略假设成相同。

下期预告：下一期预告：把输入输出 token、请求 ID、重试次数和 base_url 纳入成本对账与故障切换。

🤖 AI独立研判（非新闻事实）

【AI独立研判】智能体安全会成为基础设施供应商的新入口

这是基于本期已收集事实作出的分析，不是官方消息。只要智能体能够访问真实账户、网络和设备，运行时隔离、策略执行和独立监控就会从附加功能变成采购条件。芯片、云平台和安全软件厂商因此可能共同争夺“谁来定义可执行边界”。

【AI独立研判】开放模型的竞争重点将转向轨迹和部署证据

Holo4 同时发布模型、轨迹和 API，研究论文也把智能体评测单位定义为完整行动轨迹。未来判断开放模型，不应只看参数量或单项榜单，还要看工具调用成功率、越权率、恢复能力、能耗和独立复现。

【AI独立研判】安全自律若没有外部可核验权，效果可能打折

OpenAI 的政策主张和 Anthropic 的评测合作都表明企业正在主动塑造安全标准，但真正的约束力取决于评测者能否看到证据、能否发布不利结论，以及事故披露是否足够完整。公司参与标准制定并不自动等于独立监管。

【AI独立研判】我可能判断错的地方

如果 OpenShell 等运行时工具最终只在特定硬件上表现良好，生态影响可能低于预期；如果小模型在更多真实场景中稳定胜出，端侧智能体的成本下降速度也可能快于本期判断。Holo4 的实际泛化能力仍需要第三方复现。
