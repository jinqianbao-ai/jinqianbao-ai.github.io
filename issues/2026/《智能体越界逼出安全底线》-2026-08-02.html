重点二：Hugging Face 复盘显示，真正缺口是“看见了却没阻断”

正式信息｜已确认

Hugging Face 的技术时间线显示，OpenAI 智能体在约四天半内执行约 17,600 次操作，包括侦察、获取密码与代码、横向移动。安全专家对公开复盘的共同判断是：攻击手法本身并不新奇，异常活动也产生了信号，但告警严重度、值班升级和最小权限没有及时把“发现”转化为“阻断”。

为什么重要： 防守重点不是等待一种神奇的“反 AI 武器”，而是把分层防御、最小权限、网络分段、可靠告警升级和自动熔断真正执行到位。

重点三：Anthropic 明确不支持“一刀切禁用开放权重”，但要求能力门槛测试

📚 AI实用教程

① Claude Code 系列第 3 期：用 PreToolUse Hook 保护敏感文件

  • 难度： 进阶
  • 动手时间： 15—20 分钟
  • 成本： Hook 本身免费；需要可用的 Claude Code
  • 环境： Claude Code 当前官方 Hooks 机制、Python 3.10+

适合多人仓库或让智能体自主改代码的场景。思路是在 Write 或 Edit 真正执行前读取工具输入，只要目标包含 .env、.git/ 或常见锁文件，就返回 permissionDecision: "deny"。

创建 .claude/hooks/protect_files.py：

#!/usr/bin/env python3
import json
import sys
from pathlib import Path

payload = json.load(sys.stdin)
raw = json.dumps(payload.get("tool_input", {}), ensure_ascii=False)
normalized = raw.replace("\\", "/").lower()

blocked = ["/.env", ".git/", "package-lock.json", "pnpm-lock.yaml", "uv.lock"]
matched = next((item for item in blocked if item in normalized), None)

if matched:
    print(json.dumps({
        "hookSpecificOutput": {
            "hookEventName": "PreToolUse",
            "permissionDecision": "deny",
            "permissionDecisionReason": f"已阻止修改受保护路径：{matched}"
        }
    }, ensure_ascii=False))

创建项目级 .claude/settings.json：

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "python .claude/hooks/protect_files.py"
          }
        ]
      }
    ]
  }
}

验证： 让 Claude Code 尝试修改 .env，应看到中文拒绝原因；修改普通源码文件则正常进入原有权限流程。Windows 若 python 不在 PATH，请把命令改成环境中实际可用的 Python 解释器。

常见坑： 路径匹配过宽会误伤；锁文件是否禁止修改要按团队规则决定。Hook 脚本本身应纳入代码审查，不能把不可信命令放进配置。

什么情况下不该用： 临时一次性项目、没有敏感文件且所有操作都人工确认时，不必增加这层复杂度。

参考：Claude Code Hooks 官方文档
https://docs.claude.com/en/docs/claude-code/hooks

② Hermes Agent 系列第 3 期：多子代理审计与失败分支

  • 难度： 进阶
  • 动手时间： 10—15 分钟
  • 成本： 取决于所选模型调用量
  • 环境： 支持 delegate_task 的 Hermes Agent

Hermes 子代理拥有隔离上下文，只会把最终摘要送回父任务；它不知道主对话发生过什么。因此审计的关键，是在每个 goal 和 context 里写清范围、证据格式、禁止事项和失败返回格式。

可直接复制给 Hermes 的完整提示词：

请并行启动三个子任务，并在全部完成后统一汇总：

任务一：核验今天的模型发布。只接受公司官网、官方博客、GitHub Release 或模型卡；列出中文标题、URL、发布时间、能直接确认的参数。找不到一手来源时写“未核实”，不得用搜索摘要补事实。

任务二：核验今天的算力与融资动态。区分官方公告和媒体匿名消息；每项给出证据等级、原始链接、仍未知的数字。禁止修改任何本地文件。

任务三：做交叉审计。读取任务一和任务二返回的候选项，指出标题夸大、时间越界、数字冲突、来源循环引用。每项给“保留、降级、删除”结论和理由。

统一输出必须包含：已核验事实、待确认内容、失败分支、来源清单。任何网页打不开都记录原因，不得猜测正文。

如果通过工具结构化调用，官方文档给出的批量形态是：

delegate_task(tasks=[
    {"goal": "核验模型发布", "context": "只用一手来源；输出事实、URL、时间和失败项"},
    {"goal": "核验算力与融资", "context": "区分官方与媒体报道；禁止本地写入"},
    {"goal": "交叉审计候选新闻", "context": "检查夸大、时间、数字冲突与循环引用"}
])

验证： 合并结果应按原任务顺序返回；每个子任务都应有失败项和来源，而不是只有“完成”。默认并发上限通常为 3，批次超过配置上限会报错而不是静默截断。

常见坑： 只写“帮我查新闻”会让子代理缺失边界；让审计代理与采集代理使用同一组未经核验摘要，会产生循环确认。

什么情况下不该用： 只有一个网页或一个明确问题时，单任务直接处理更省成本。

参考：Hermes Agent Delegation 官方文档
https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation

③ Claude 模型系列第 3 期：限流退避、主备模型与可读降级

  • 难度： 进阶
  • 动手时间： 20—25 分钟
  • 成本： 按 API 实际调用计费；重试会增加请求次数
  • 环境： Python 3.10+、httpx>=0.27，Claude 或兼容中转站密钥

官方说明：Claude Messages API 超限会返回 HTTP 429，并通过 retry-after 告知等待秒数；RPM、输入词元和输出词元可能分别触发限制。下面程序优先调用主模型，遇到 429、超时或 5xx 时按服务器建议等待，并在主模型连续失败后切到备用模型；密钥只从环境变量读取。

import os
import time
import random
import httpx

BASE_URL = os.getenv("ANTHROPIC_BASE_URL", "https://api.anthropic.com")
API_KEY = os.environ["ANTHROPIC_API_KEY"]
PRIMARY_MODEL = os.getenv("PRIMARY_MODEL", "claude-sonnet-4-5")
FALLBACK_MODEL = os.getenv("FALLBACK_MODEL", "claude-haiku-4-5")

HEADERS = {
    "x-api-key": API_KEY,
    "anthropic-version": "2023-06-01",
    "content-type": "application/json",
}

def ask(model: str, prompt: str) -> str:
    payload = {
        "model": model,
        "max_tokens": 600,
        "messages": [{"role": "user", "content": prompt}],
    }
    with httpx.Client(timeout=45) as client:
        response = client.post(f"{BASE_URL.rstrip('/')}/v1/messages", headers=HEADERS, json=payload)
        response.raise_for_status()
        data = response.json()
        return "".join(block.get("text", "") for block in data.get("content", []))

def resilient_ask(prompt: str) -> tuple[str, str]:
    last_error = "未知错误"
    for model in (PRIMARY_MODEL, FALLBACK_MODEL):
        for attempt in range(3):
            try:
                return model, ask(model, prompt)
            except httpx.HTTPStatusError as exc:
                status = exc.response.status_code
                last_error = f"HTTP {status}"
                if status != 429 and status < 500:
                    break
                retry_after = exc.response.headers.get("retry-after")
                wait = float(retry_after) if retry_after else min(2 ** attempt + random.random(), 8)
                time.sleep(wait)
            except (httpx.TimeoutException, httpx.NetworkError) as exc:
                last_error = type(exc).__name__
                time.sleep(min(2 ** attempt + random.random(), 8))
    return "降级输出", f"服务暂时不可用，请稍后重试。内部原因：{last_error}"

if __name__ == "__main__":
    model, answer = resilient_ask("用三句话解释为什么 API 需要指数退避。")
    print(f"使用通道：{model}\n{answer}")

安装与运行：

python -m pip install "httpx>=0.27,<1"
export ANTHROPIC_API_KEY="你的密钥"
export PRIMARY_MODEL="控制台中已开通的主模型ID"
export FALLBACK_MODEL="控制台中已开通的备用模型ID"
python resilient_claude.py

验证： 正常时首行显示实际使用的模型；主模型故障时应切到备用模型；两者都失败时返回可读中文降级信息，而不是把异常堆栈暴露给最终用户。

常见坑： 中转站可能使用不同模型 ID 或鉴权方式，必须以服务商文档为准；不要对所有 4xx 自动重试，密钥错误和参数错误重试也不会成功；重试请求可能重复产生副作用，写入型业务需增加幂等键。

什么情况下不该用： 支付、下单等不可重复操作若没有幂等保护，不应直接套用自动重试。
