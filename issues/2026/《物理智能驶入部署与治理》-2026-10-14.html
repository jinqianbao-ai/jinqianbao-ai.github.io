Claude Code系列｜第42期：用Hooks把敏感文件与测试变成自动门槛

难度：进阶｜动手时间：45—60分钟｜成本：免费；Claude调用按账号计费｜环境：Claude Code、Python 3.10+、Git项目

目标：上一期建立了提交前门槛，本期把门槛变成确定性Hooks（钩子）：写入前拦截.env和密钥文件，写入后自动运行测试。官方文档说明，PreToolUse可在工具执行前阻止操作，PostToolUse可在成功后运行脚本。

  1. 在项目中新建.claude/hooks/guard.py：
import json, sys
event = json.load(sys.stdin)
path = str(event.get("tool_input", {}).get("file_path", "")).replace("\\", "/").lower()
blocked = ("/.env", "/secrets/", "id_rsa", "credentials.json")
if any(x in "/" + path for x in blocked):
    print(json.dumps({
        "hookSpecificOutput": {
            "hookEventName": "PreToolUse",
            "permissionDecision": "deny",
            "permissionDecisionReason": "禁止由编码代理修改密钥或凭证文件"
        }
    }, ensure_ascii=False))

2. 在.claude/settings.json写入完整配置：

{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Write|Edit",
      "hooks": [{"type": "command", "command": "python .claude/hooks/guard.py"}]
    }],
    "PostToolUse": [{
      "matcher": "Write|Edit",
      "hooks": [{"type": "command", "command": "python -m pytest -q", "timeout": 120}]
    }]
  }
}

验证：让Claude Code尝试修改普通测试文件，测试应自动运行；尝试修改.env时应被拒绝。若Windows找不到python，把命令改成项目虚拟环境解释器的明确路径。

常见坑：不要只在CLAUDE.md写“禁止改密钥”，那是指导而非强制边界；测试较慢时，应换成受影响测试集，避免每次编辑都跑全量套件。

什么情况下不该用这个方法：项目没有稳定测试或钩子命令本身会改生产数据时，先不要自动运行。

参考：https://docs.anthropic.com/en/docs/claude-code/hooks

Hermes Agent系列｜第42期：多子代理只交付结构化结果

难度：进阶｜动手时间：35—50分钟｜成本：按子代理模型调用计费｜环境：支持delegate_task的Hermes Agent

目标：上一期建立外部写入证据链，本期把调研、审查和事实核验拆给互不共享上下文的子代理，并要求它们只返回固定字段。官方文档说明，子代理拥有隔离上下文，只会把最终摘要带回父代理，因此父代理必须把完整目标、范围和输出格式写进任务。

可直接复制给Hermes：

请并行启动三个子代理：
1. 一手来源核验员：只找官方公告、论文和发布页；
2. 反方审查员：专门找数字冲突、时间错误和过度推断；
3. 教程审查员：检查命令是否来自官方文档、是否含真实密钥。
每个子代理必须按以下六行返回，不得自由发挥：
结论：通过／不通过
已核验事实：最多5条
来源URL：逐行列出
不确定项：逐行列出
建议修改：最多5条
是否允许发布：是／否
父代理只有在三份结果都返回后才能综合；任何“否”必须对应修复或明确降级可信度。

对应的工具调用结构：

delegate_task(tasks=[
  {"goal": "核验一手来源", "context": "完整材料、时间范围、六行输出格式"},
  {"goal": "做反方事实审查", "context": "完整材料、重点数字、六行输出格式"},
  {"goal": "审查教程可运行性", "context": "完整教程、官方参考、六行输出格式"}
])

验证：父代理收到的每份结果都应包含六个字段；缺字段视为未完成，不能靠父代理猜测补齐。子代理互相依赖时不要并行，应改成“研究→审查→综合”的串行链。

常见坑：子代理不知道父对话里的“这个文件”“刚才的错误”；必须在context里写清路径、错误和验收标准。并行数要服从当前配置上限。

什么情况下不该用这个方法：只有一次简单查找或一个机械命令时，直接使用工具更省成本。

参考：https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation

ledger = json.loads(LEDGER.read_text("utf-8")) if LEDGER.exists() else {}
spent = float(ledger.get(today, 0.0))
budget = float(os.environ["DAILY_BUDGET_USD"])
if spent >= budget:
    raise SystemExit(f"今日预算已用完：${spent:.4f} / ${budget:.4f}")
providers = [
    ("主服务", "PRIMARY"),
    ("备用服务", "BACKUP"),
]
last_error = None
for label, prefix in providers:
    try:
        client = OpenAI(
            api_key=os.environ[f"{prefix}_API_KEY"],
            base_url=os.environ[f"{prefix}_BASE_URL"],
            timeout=30,
        )
        r = client.responses.create(
            model=os.environ[f"{prefix}_MODEL"],
            input="用三句话说明为什么智能体必须设置权限边界。",
        )
        usage = r.usage
        in_price = float(os.environ["INPUT_USD_PER_M"])
        out_price = float(os.environ["OUTPUT_USD_PER_M"])
        cost = usage.input_tokens / 1_000_000 * in_price + usage.output_tokens / 1_000_000 * out_price
        if spent + cost > budget:
            raise RuntimeError("本次调用会突破每日预算")
        ledger[today] = round(spent + cost, 6)
        LEDGER.write_text(json.dumps(ledger, ensure_ascii=False, indent=2), "utf-8")
        print(f"使用{label}，本次估算${cost:.6f}，今日累计${ledger[today]:.6f}")
        print(r.output_text)
        break
    except Exception as exc:
        last_error = exc
else:
    raise SystemExit(f"主备服务均失败：{last_error}")

验证：首次运行应生成ai-cost-ledger.json并输出本次估算费用；把每日预算设得极低，应在调用前或计费检查处停止。此脚本是客户端估算，月底必须与服务商Usage/Costs账单对账。

常见坑：主备模型价格可能不同，生产版应分别配置价格；部分中转站不支持Responses API或不返回标准usage，遇到这种情况应换用其官方接口并明确标注“无法自动对账”。

什么情况下不该用这个方法：涉及严格财务结算时，不要把客户端估算当最终账单。
